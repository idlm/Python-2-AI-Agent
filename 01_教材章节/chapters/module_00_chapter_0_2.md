| 使用基础终端命令 | 能用命令确认目录、列出文件、切换目录和运行脚本。 |

## 2. 为什么学习

许多初学者把编程困难误认为“代码逻辑太复杂”，其实第一个障碍常常是运行环境：文件放在哪里、终端现在在哪个目录、输入的 `python` 是不是你刚安装的 Python、为什么双击能打开却不能运行、为什么别人复制的命令在自己电脑上报错。若这些问题没有模型，后续遇到 `pip`、虚拟环境、Git、数据库迁移、Docker 或 API 服务时，都会变成无法解释的操作仪式。

Python 的官方文档说明，解释器可以以交互模式读取命令，也可以接收文件名并执行其中的脚本；还可以使用 `-c` 执行一段命令，或使用 `-m` 按模块方式运行代码。[1] 这不是需要立刻记住的选项表，而是在告诉我们：**同样是“运行 Python”，入口不同，输入不同，程序的定位方式和行为也会不同。**

## 3. Agent 中的作用

将来你的 Agent 平台不会只是一份 Python 文件。它会由 API 服务、数据库、向量索引、后台任务、模型客户端、配置文件、日志和容器组成。每个部分都必须由正确的程序在正确的目录、正确的环境中启动；每个部分也都会产生日志、缓存、状态文件和错误信息。

例如，生产环境中“Agent 没有读取到知识库”可能不是检索算法问题，而是容器内工作目录不同、挂载路径错误、配置文件未加载或运行了错误版本的服务。今天理解工作目录与解释器，等于提前学习一种根因分析习惯：当行为不符合预期时，先确认**实际运行的是谁、它从哪里读文件、它看到了什么输入**。

## 4. 前置知识

本章不要求你会写 Python。你只需能够打开终端并按原样输入命令。请不要在不了解含义时运行从互联网复制来的破坏性命令，尤其是包含删除、覆盖、管理员权限、下载并执行或要求输入密钥的命令。本章所有命令只会查看信息、创建一个安全的练习目录或运行本章提供的 Python 文件。

本章以 Linux/macOS 风格的 Bash 命令展示：`pwd`、`ls`、`cd` 和 `python3`。Windows PowerShell 的常用等价命令是 `Get-Location`、`Get-ChildItem`、`Set-Location` 和 `py` 或 `python`；具体 Python 启动方式取决于安装方式。Python 官方教程也说明，在 Windows 上可以使用 `py` 启动器，在 Unix 类系统上通常通过 `python3.x` 命令启动解释器。[2]

| 你的系统 | 本章主要命令 | 常见替代 | 不确定时先做什么 |
|---|---|---|---|
| Linux / macOS | `pwd`、`ls`、`cd`、`python3` | 某些系统也支持 `python`。 | 输入 `python3 --version`。 |
| Windows PowerShell | `Get-Location`、`Get-ChildItem`、`Set-Location`、`py` | 也可尝试 `python`。 | 输入 `py --version` 或 `python --version`。 |
| Windows 命令提示符 | `cd`、`dir`、`py` | `python`。 | 输入 `py --version`。 |

## 5. 概念解释

**程序（Program）**是让计算机执行一组操作的说明和相关数据。`runtime_snapshot.py` 是一个源代码文件，但它本身不是正在运行的程序；只有当解释器读取它并开始执行时，才产生一次运行。

**源代码（Source Code）**是人编写的文本，例如 Python 文件中的 `print("你好")`。它需要由某个工具理解。对于 Python，常见工具是 Python 解释器（Interpreter）。解释器读取 Python 源代码，检查语法，创建运行需要的数据结构，并按规则执行。

**终端（Terminal）**是一个让你用文字与计算机交互的界面。终端里通常运行着一个**命令行解释器（Shell）**，例如 Bash、zsh、PowerShell 或 Windows 的命令提示符。Shell 负责理解 `cd`、`ls`、`python3` 这些操作系统命令；Python 解释器则负责理解 `if`、`print`、`def` 这些 Python 代码。两者名称相似，职责却完全不同。

**文件（File）**是带有名称和内容的数据单元；**目录（Directory）**是组织文件和其他目录的容器。**路径（Path）**是告诉系统“到哪里寻找文件”的地址。你此刻所在的位置叫**当前工作目录（Current Working Directory，CWD）**。当命令使用相对路径时，系统会以 CWD 为起点查找；因此路径不变、CWD 改变，实际找到的文件也可能不同。

| 概念 | 作用 | 例子 | 常见误解 |
|---|---|---|---|
| Shell | 接收并执行操作系统命令。 | Bash 执行 `cd examples`。 | 以为它就是 Python。 |
| Python 解释器 | 读取并执行 Python 代码。 | `python3 demo.py`。 | 以为安装编辑器就等于安装 Python。 |
| 源代码文件 | 保存 Python 指令文本。 | `runtime_snapshot.py`。 | 以为双击文件就是唯一运行方式。 |
| 当前工作目录 | 相对路径的起点。 | `/home/alex/course`。 | 以为它永远等于脚本所在目录。 |
| 进程 | 一次正在运行的程序实例。 | 当前正在执行的 Python。 | 以为同一文件只能运行一次。 |

## 6. 生活化比喻

把一次程序运行想成去图书馆找书。终端是服务台，你说出请求；Shell 是馆员，负责根据你的话去查目录；路径是书架地址；Python 解释器是能够读懂“Python 语言”的译员；源代码是那本用 Python 写成的说明书；输出是译员读完后交给你的结果。当前工作目录像你此刻站着的楼层——当你只说“去 A 区”时，起点楼层不同，可能走到不同地方。

这个比喻的边界是：计算机不会像人一样根据常识猜测你的意思。若路径错一个字符、文件名大小写不同、解释器不是预期版本，它通常不会“帮你找差不多的那个”，而是给出错误。因此，明确路径、版本和命令比“看起来应该能运行”更可靠。

## 7. 原理分析

从命令到输出，可以拆成下列八个步骤。以后遇到环境错误时，按这个链条逐项排查，而不是同时修改多个东西。

```text
1. 你在终端键入命令
2. Shell 解析命令和参数
3. Shell 按搜索规则找到要运行的可执行程序
4. 操作系统启动一个新进程
5. Python 解释器读取脚本路径和当前环境
6. Python 解析源代码并执行语句
7. 程序访问文件、网络或其他输入，产生状态变化
8. 标准输出或错误输出回到终端
```

以 `python3 examples/module_00/runtime_snapshot.py` 为例，`python3` 是要启动的解释器，后面的文本是传给解释器的脚本路径。Python 文档把这种形式描述为“以文件名参数调用解释器”；解释器会读取并执行该脚本。[1] 如果 Shell 在第 3 步找不到 `python3`，你得到的是 Shell 层面的“命令未找到”；如果 Python 在第 5 步找不到脚本，得到的是“无法打开文件”；如果 Python 在第 6 步读到无效语法，则得到 `SyntaxError`。错误发生层次不同，修复方式也不同。

路径有两种常见写法。**绝对路径**从文件系统根位置开始，例如 Linux 的 `/home/alex/python_private_course/examples/module_00/runtime_snapshot.py` 或 Windows 的 `C:\Users\Alex\python_private_course\examples\module_00\runtime_snapshot.py`。**相对路径**从当前工作目录出发，例如 `examples/module_00/runtime_snapshot.py`。初学时推荐先在项目根目录运行相对路径：它更短，也能让项目整体移动到新位置后仍然可运行；排错时再用绝对路径确认你指向的是不是同一个文件。

## 8. 最小示例

在项目根目录创建或打开 `examples/module_00/runtime_snapshot.py`，写入以下代码。这个程序不会修改任何文件，只报告本次运行的环境信息。

```python
"""第 0.2 章：观察 Python 程序的运行环境。支持 Python 3.11+。"""

from pathlib import Path
import sys


def describe_runtime() -> list[str]:
    """返回本次 Python 运行的可观察信息。"""
    return [
        f"Python 可执行文件：{sys.executable}",
        f"Python 版本：{sys.version_info.major}.{sys.version_info.minor}",
        f"当前工作目录：{Path.cwd()}",
        f"脚本文件名：{Path(__file__).name}",
    ]


def main() -> None:
    for line in describe_runtime():
        print(line)


if __name__ == "__main__":
    main()
```

在终端先进入项目根目录，再确认位置、查看文件并运行程序：

```bash
pwd
ls examples/module_00
python3 examples/module_00/runtime_snapshot.py
```

输出中的完整路径会因你的电脑不同而变化；这正是本例的目的。你至少会看到四行：解释器的位置、主次版本号、当前工作目录和脚本文件名。例如：

```text
Python 可执行文件：/usr/bin/python3
Python 版本：3.11
当前工作目录：/home/alex/python_private_course
脚本文件名：runtime_snapshot.py
```

接下来故意切换到 `examples` 目录，再运行相对路径：

```bash
cd examples
python3 module_00/runtime_snapshot.py
```

这一次“当前工作目录”会变成项目中的 `examples` 目录，而脚本文件名仍是 `runtime_snapshot.py`。这证明：**脚本所在位置与当前工作目录是两个不同概念。**

## 9. 逐行解释

| 代码位置 | 它做了什么 | 你需要抓住的原理 |
|---|---|---|
| 第 1 行 | 用模块说明记录本文件用途与 Python 版本。 | 代码文件也应让后来的人知道它解决什么问题。 |
| 第 3 行 | 导入 `Path`，用于以对象形式处理路径。 | 路径不是神秘字符串，可以被程序读取和操作。 |
| 第 4 行 | 导入 `sys`，它提供解释器和运行环境的信息。 | 程序可以观察自己正在哪里、以什么方式运行。 |
| `describe_runtime` | 返回四条环境信息，而不是直接打印。 | 将“收集信息”和“显示信息”分开，更容易测试。 |
| `sys.executable` | 取得当前 Python 解释器的可执行文件路径。 | 运行的解释器可以与编辑器显示的解释器不同。 |
| `sys.version_info` | 取得结构化版本信息。 | 版本应作为数据比较，而不是只看一段文字。 |
| `Path.cwd()` | 取得当前工作目录。 | 相对路径默认以此为起点。 |
| `Path(__file__).name` | 取得当前源代码文件的名称。 | 脚本自身位置与 CWD 不必相同。 |
| `for ... print` | 逐条打印函数返回的信息。 | 输出顺序也是程序的一部分。 |
| 最后两行 | 当文件作为主程序运行时，执行 `main()`。 | 导入模块进行测试时，不应自动打印信息。 |

## 10. 常见错误

| 终端现象 | 错误层次 | 最常见原因 | 第一步检查 |
|---|---|---|---|
| `python3: command not found` | Shell 找不到解释器。 | Python 未安装，或命令搜索路径未配置。 | `python --version`、`py --version` 或检查安装方式。 |
| `can't open file ... No such file or directory` | Python 找不到脚本。 | 当前工作目录不对，或相对路径写错。 | 先执行 `pwd` 与 `ls`，再核对文件名。 |
| `SyntaxError` | Python 无法理解源代码。 | 漏掉冒号、引号、括号或缩进不正确。 | 读 Traceback 的文件名、行号和尖号。 |
| `ModuleNotFoundError` | Python 找不到要导入的模块。 | 启动位置、环境或依赖安装位置不一致。 | 确认 `sys.executable` 与依赖安装时的解释器一致。 |
| 双击后窗口一闪而过 | 图形界面启动脚本后立即退出。 | 没有保留输出的终端窗口。 | 用终端运行，保留命令和输出证据。 |

## 11. Traceback 分析

假设你在项目根目录误输入了下面的命令：

```bash
python3 examples/module_00/runtime-snapshot.py
```

文件实际名是下划线 `_`，你却写成了连字符 `-`。会看到类似输出：

```text
python3: can't open file '.../examples/module_00/runtime-snapshot.py': [Errno 2] No such file or directory
```

这不是 Python 代码语法错误。解释器已经成功启动，但它拿到的脚本路径不存在。因此不要马上打开代码改 `print()` 或缩进；应回到第 5 步：运行 `ls examples/module_00`，看文件名是否与命令逐字符一致。另一种常见错误是在 `examples` 目录里仍输入完整的 `examples/module_00/...` 相对路径，这会让系统去寻找 `examples/examples/module_00/...`，同样找不到文件。

## 12. 错误案例

一个新手常见的排错过程是：运行命令失败后，连续尝试 `python`、`python3`、`py`、`sudo python`、重新安装编辑器、复制陌生命令、移动文件、修改代码，最后不知道哪一步造成了变化。这种做法叫作“多变量同时修改”，它会摧毁证据链。

另一个错误案例是把路径写死在代码中：

```python
report_path = "/home/alex/Desktop/我的项目/报告.txt"
```

它在 Alex 的电脑上可能运行，在另一台电脑、容器或服务器上就会失败。这个问题不是“Alex 的路径写得不对”，而是程序把某台机器的偶然环境误当成了通用规则。后续我们会用配置、相对路径与 `pathlib` 解决这类问题。

## 13. 改进方案

改进环境问题的通用步骤是“一次只确认一层”。先确认 Shell 真的找到了 Python：`python3 --version`。再确认当前目录：`pwd`。再确认文件存在：`ls examples/module_00`。再运行脚本。最后让脚本打印 `sys.executable` 与 `Path.cwd()`，确认运行时事实。每一步都有短小、可重复、可记录的输出。

对于跨电脑项目，优先使用相对路径和项目目录结构，而不是把个人目录写死。对于需要外部配置的程序，后续会将文件位置、端口、密钥等信息放在环境变量或配置文件中，并写出示例配置；但是配置文件也必须记录由谁读取、缺失时怎样报错、是否包含敏感数据。

## 14. 工程实践

从本章开始，建立一个“环境快照”习惯。每次出现“我的电脑能运行、你的不能”时，先记录以下信息：操作系统、Python 命令、`--version` 输出、`sys.executable`、当前工作目录、项目提交版本和完整错误信息。不要只发一张模糊截图或一句“报错了”。一条完整的环境快照常常能把排错时间从几十分钟缩短到几分钟。

建议目录中每个项目都保留一个 `README.md`，至少写明四件事：如何进入项目目录、如何安装依赖、如何运行、预期输出是什么。后续会把这四件事扩展成测试、配置、数据库、容器和部署说明，但今天先做到“别人按文字也能运行第一条命令”。

## 15. 性能优化

本章脚本运行极快，不需要微优化。这里值得建立的是另一种性能观：**减少人等待反馈的时间。** 使用小而稳定的命令、短路径、明确输出和可复制的环境快照，比把所有信息藏在复杂图形界面里更容易快速定位问题。

随着项目变大，启动时间、导入时间、磁盘访问和网络调用会变成真正的性能因素。届时不能靠直觉猜“哪儿慢”，而要用测量工具和日志。不过，无论系统多复杂，确认正在使用哪个解释器、哪个工作目录和哪个文件，仍然是最低成本的第一步。

## 16. 安全问题

终端命令具有直接操作文件、网络和进程的能力，因此“看不懂的命令不运行”是一条工程安全规则。特别警惕以下组合：要求管理员权限的命令、删除或递归覆盖目录的命令、从网络下载后立即执行的命令、要求粘贴 API 密钥或会话令牌的命令。即使来源看似可信，也应先理解命令影响的路径、权限和副作用。

Python 文档说明，解释器可以执行脚本、`-c` 参数中的代码和 `-m` 指定的模块。[1] 这种灵活性很有用，也意味着命令行应被视为执行边界：不要把不可信文本直接拼进 `python -c`；不要让未来的 Agent 把未经验证的自然语言转换成可执行 Shell 命令；涉及文件删除、账户操作或数据外发的工具必须具备明确审批和最小权限。

## 17. 小项目：我的环境体检报告

创建一个名为 `environment_report.md` 的文件，完成一份可复现的环境体检报告。报告不需要透露个人隐私路径；可以将用户名替换成 `<你的用户名>`。它的目标是让另一个人仅凭报告就能判断：你用什么 Python、从哪个目录运行、项目文件是否放在预期位置，以及运行是否成功。

| 报告部分 | 必填内容 | 验收条件 |
|---|---|---|
| 运行命令 | 你实际执行的 `python3 --version`、`pwd`、`ls` 与脚本运行命令。 | 命令可复制，路径无模糊省略。 |
| 输出摘要 | Python 主次版本、解释器路径、CWD、脚本名。 | 与 `runtime_snapshot.py` 的输出一致。 |
| 一次失败记录 | 故意写错一个文件路径并记录报错。 | 能指出错误发生在运行链路的哪一层。 |
| 恢复说明 | 你如何更正命令并成功运行。 | 不通过重装所有软件来解决。 |

## 18. 单元测试

下面的测试验证 `describe_runtime()` 返回的不是随机文本：它必须包含解释器、版本、工作目录和脚本名四类信息。将文件保存为 `05_教学测试/tests/module_00/test_runtime_snapshot.py`。

```python
"""第 0.2 章示例的单元测试。支持 Python 3.11+。"""

import unittest

from examples.module_00.runtime_snapshot import describe_runtime


class RuntimeSnapshotTests(unittest.TestCase):
    def test_snapshot_contains_four_runtime_facts(self) -> None:
        lines = describe_runtime()
        self.assertEqual(len(lines), 4)
        self.assertTrue(lines[0].startswith("Python 可执行文件："))
        self.assertTrue(lines[1].startswith("Python 版本："))
        self.assertTrue(lines[2].startswith("当前工作目录："))
        self.assertEqual(lines[3], "脚本文件名：runtime_snapshot.py")


if __name__ == "__main__":
    unittest.main()
```

在项目根目录执行：

```bash
python3 -m unittest 05_教学测试/tests/module_00/test_runtime_snapshot.py
```

测试使用 `-m unittest`，意味着让 Python 按模块方式运行标准库中的测试工具；官方文档说明 `-m` 会按标准导入机制定位并执行指定模块。[1] 现在你不必掌握 `unittest` 的全部 API，只要注意测试检查的是“程序行为是否符合约定”，而不是“某次手工运行有没有看起来正常”。
