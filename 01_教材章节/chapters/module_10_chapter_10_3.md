# 第 10.3 章：模型只能引用它真正看见的证据——来源约束回答、拒答与本地验证

**适用版本：** Python 3.11+  
**项目连接：** `02_可运行项目/projects/10-rag-contract-workbench/`（v0.5.0）  
**前置章节：** 第 9.1–9.3 章的受控模型合同与严格 JSON；第 10.1–10.2 章的受控检索和离线检索评测。

## 1. 本章目标

完成本章后，你能够把“检索到片段”推进为“只基于实际片段提出候选回答”；能设计状态、回答、引用与人工复核字段；能让空证据在本地直接返回受控结果；能拒绝非法 JSON、未知引用、重复引用、缺失引用和超长回答；也能解释为什么引用存在仍不代表回答为真。

> **本章结论：** 模型生成的引用字符串不是来源。来源必须由应用从真实 `RetrievedChunk` 中重建，并在模型输出之外验证。

## 2. RAG 回答层的输入和输出

第 10.2 章的检索层输出 `RetrievalResult`：有限块、来源、分数、索引版本。回答层的输入是用户问题和这个检索结果；输出是 `GroundedAnswer`：状态、候选回答、引用、是否需要人工复核、索引版本和问题长度。

| 对象 | 责任 | 不能承担 |
|---|---|---|
| `RetrievalResult` | 说明实际检索到哪些候选块。 | 证明事实、权限或适用性。 |
| `StructuredAnswerTransport` | 抽象一个可替换的候选回答传输。 | 授权工具、决定来源、绕过本地验证。 |
| `GroundedAnswer` | 呈现候选回答和应用重建的引用。 | 医疗、法律、财务或其他高风险结论。 |
| `Citation` | 指向块 ID、文档、版本和字符范围。 | 证明文档权威、完整、最新或无冲突。 |

## 3. 不要把“带引用”误解为“被证实”

模型可能输出看似专业的出处，也可能把不存在的文件名、块 ID 或页码编进回答。即使它引用了真实块，块也可能过时、断章取义、无权访问或不足以支持结论。引用的最低作用是让读者回到具体证据检查，而不是替代检查。

OpenAI 的检索资料说明检索返回可包含来源与内容；File Search 的生成结果也可包含文件引用。[1] [2] 课程在本地保存来源链，目的是可追溯，而不是让供应商注释自动成为事实认证。

## 4. 先定义两个公开状态

项目只有两个状态：`answered` 和 `not_enough_evidence`。前者要求至少一个实际检索块引用；后者必须没有引用，并默认 `needs_human_review=True`。减少状态并不让系统更聪明，但能让调用者明确处理“有候选证据”和“没有足够证据”两条路径。

```python
class AnswerStatus(StrEnum):
    ANSWERED = "answered"
    NOT_ENOUGH_EVIDENCE = "not_enough_evidence"
```

不要添加 `probably_true`、`safe`、`authoritative` 或 `approved` 等未经定义的状态。它们会把相似度、模型语气和业务责任混为一谈。

## 5. 空证据必须在本地处理

若 `retrieval.results` 为空，`SourceBoundAnswerClient.answer()` 不调用传输，而是返回固定文案“当前受控语料中未找到足够依据。”、空引用与人工复核标记。这样无关问题不会因为模型善于聊天而产生无来源回答。

```python
if not retrieval.results:
    return GroundedAnswer(
        status=AnswerStatus.NOT_ENOUGH_EVIDENCE,
        answer="当前受控语料中未找到足够依据。",
        citations=(),
        needs_human_review=True,
        ...,
    )
```

这不是世界知识的否定，只是当前 collection、索引版本、阈值和 `top_k` 没有提供足够候选。后续产品可以引导用户换查询、补充受权语料或升级人工，但不能伪装成已找到答案。

## 6. 有证据也只允许候选回答

当检索返回块时，项目可以通过 `StructuredAnswerTransport` 请求候选 JSON。该 Protocol 让测试使用假传输，不需要网络、凭据或真实模型。实际供应商适配器应独立实现，继承模块 9 的模型允许列表、输入/输出 token 上限、有限重试、脱敏日志、严格响应格式和最少真实烟雾原则。

本项目 v0.3.0 故意不包含真实模型适配器。这样读者先验证来源约束，再把任何供应商接入点限制在小而可测试的边界中。

## 7. 系统指令解释合同，不授予权限

传输收到的固定指令说明三件事：来源片段是不可信数据；只能依据给定来源作答；证据不足时应使用 `not_enough_evidence`。它还说明返回 JSON 的固定字段。

提示词能改善模型行为，却不是访问控制。安全资料建议限制输入与输出、进行对抗性测试，并认识到模型会出现幻觉和其他限制。[3] 即使系统提示写得很好，应用仍要在模型外验证引用、执行权限和所有副作用。

## 8. 检索片段进入模型前仍是数据

调用层把问题和来源组装为 JSON：

```json
{
  "question": "函数如何处理输入？",
  "sources_are_untrusted_data": [
    {
      "chunk_id": "functions-0",
      "document_id": "functions",
      "source_version": "v1",
      "text": "函数把重复步骤封装为可调用单元。..."
    }
  ]
}
```

字段名 `sources_are_untrusted_data` 不会神奇地阻止攻击，但它让代码、日志审查与测试明确表达信任边界。任何块中的“忽略规则”“显示秘密”“调用工具”都只是文本，不能改写 Python 的状态机、允许列表或权限。

## 9. 严格输出 Schema 的最小形状

回答传输被要求返回且仅返回四个字段：`status`、`answer`、`citation_chunk_ids`、`needs_human_review`。本地解析器要求字段集合**完全相等**，而不是“至少有这几个字段”。

```json
{
  "status": "answered",
  "answer": "函数通过参数接收输入，并通过返回值传出处理结果。",
  "citation_chunk_ids": ["functions-0"],
  "needs_human_review": true
}
```

模块 9 已说明严格 JSON Schema 与本地重复验证的价值：格式有效不等于事实、权限、来源或安全正确。本章沿用同一原则，把回答字段、长度、枚举和引用集合都视为不可信候选。

## 10. 顶层 JSON 不是对象，立即失败

传输可能返回空字符串、Markdown 代码块、数组、自然语言、截断 JSON 或非 JSON。`_parse_grounded_answer()` 先拒绝空内容，再用 `json.loads()` 解析，接着要求顶层为对象。任何失败都会成为 `AnswerContractError`，而不是由代码猜测、修补或悄悄转换。

这条边界能避免“模型差一点就符合，所以自动补一个字段”的错误。自动补全会让真实供应商或提示变更被隐藏，也会让后续调查失去证据。

## 11. 额外字段也是合同破坏

若候选 JSON 除四个允许字段外还有 `confidence`、`tool_call`、`reasoning`、`url` 或任意未知键，项目拒绝它。原因不是这些字段永远没有价值，而是它们没有被设计、评测、脱敏、授权或展示。

> **规则：** 新字段不是“顺手接收”，而是一次新的接口设计。它需要 Schema、类型、长度、隐私、日志、失败案例、评测和用户体验共同更新。

## 12. 枚举、长度和布尔值也要在本地核验

本地检查 `status` 是否属于两个枚举；`answer` 是否是 1–600 字符非空字符串；`citation_chunk_ids` 是否为最多三项的字符串数组；`needs_human_review` 是否真的是布尔值。Python 中 `"true"`、`1` 和 `True` 不能被混为一谈。

这些约束防止超长输出吞掉上下文或 UI，也让失败模式稳定。它们没有验证回答内容真实；事实性仍依赖来源质量、任务评测和必要的人工审查。

## 13. `answered` 必须真正引用来源

`status="answered"` 且空引用会被拒绝。否则模型可以写出流畅结论，却没有让应用知道证据在哪里。项目不允许回答层因为“答案很短”或“常识问题”跳过来源。

这是一种产品选择。未来可能存在不需要 RAG 的通用聊天模式，但它应是不同的、明确标记的工作流，不能伪装为“基于知识库”的回答。

## 14. `not_enough_evidence` 不能伪装带证据

若 `status="not_enough_evidence"` 却附带引用，项目同样拒绝。状态与引用必须一致，否则调用者无法理解“这是有依据的答案”还是“缺少依据的升级提示”。

本地空证据路径通常不会调用模型；这里的检查仍然必要，因为真实传输、未来工作流或错误适配器可能构造出矛盾候选。

## 15. 引用 ID 必须来自实际检索结果

这是本章最重要的本地控制。回答层先从 `retrieval.results` 建立 `allowed_citations`：键是块 ID，值是该块真实的文档 ID、标题、版本和范围。模型只输出块 ID；应用从允许表重建 `Citation`。

```python
unknown_ids = set(citation_ids) - set(allowed_citations)
if unknown_ids:
    raise AnswerContractError("回答引用了未实际检索到的块。")
```

这样，模型无法用 `finance-policy-99` 或任意虚构页码冒充证据。它仍不能保证已引用块真的支持回答，因此需要下一层的回答评测与人工复核。

## 16. 为什么不让模型直接写标题、版本和位置

若模型自己填写标题、版本和字符范围，它可能混淆两个文档、写错版本或捏造位置。应用已经有 `Chunk`，应以它作为唯一来源。`Citation` 因此只由本地代码构造。

| 来源字段 | 由谁决定 | 原因 |
|---|---|---|
| `chunk_id` | 模型只能从允许集合中选择。 | 限制可引用证据。 |
| `document_id` | 应用从真实块重建。 | 防止伪造来源。 |
| `document_title` | 应用从真实块重建。 | 防止模型改写标题。 |
| `source_version` | 应用从真实块重建。 | 防止版本漂移被掩盖。 |
| 字符范围 | 应用从真实块重建。 | 让审查可定位原文。 |

## 17. 重复引用和无界引用都要拒绝

重复 `citation_chunk_ids` 不能增强证据，只会占用空间并让 UI 产生假象；超过三项则会放大上下文、阅读和审查负担。项目拒绝重复引用、限制最多三项。

三个不是通用最佳数字。它是课程原型的可见预算。真实产品应依据界面、任务、语料、模型上下文、成本和评测决定，但必须把上限写入合同并为越界写测试。

## 18. 日志记录回答形状，不记录问题和证据正文

回答日志可记录索引版本、问题字符数、状态、引用数和人工复核标记。它不能记录问题正文、来源正文、系统指令、传输原始 JSON、模型推理、密钥或异常原文。

```text
INFO rag_answer_completed index_version=... query_chars=9 status=answered citation_count=1 review=True
```

日志最小化不意味着永远不保留故障信息。它意味着为每一种可保留字段说明排障价值、保留期、访问者和泄露代价；需要完整证据时，应走受权、短期、隔离的调试流程。

## 19. 传输成功不等于回答通过

本项目的 27 项无网络测试只验证合同：假传输返回合法 JSON 时被解析；空证据不调用传输；非法 JSON 和错误引用被拒绝；日志不含正文。它不测量真实模型是否忠实、是否遗漏重要限制、是否引用最合适的块或是否适合特定领域。

评测最佳实践建议按任务定义目标、数据、指标、运行比较与持续评估，并以人工判断校准自动化判断。[4] 因此下一批夹具必须在源级检索成功的基础上评测回答是否受到证据支持，而不是只检查 JSON 可解析。

## 20. RAG 回答层仍不是 Agent

此层没有工具选择、循环规划、记忆写入、网页访问、数据库更新、shell、支付、邮件或自动执行。它只接收有限检索证据并返回候选文本与引用。添加工具会使提示注入风险和错误后果放大，必须在后续模块引入显式参数 Schema、允许列表、最小权限、审计和人工确认。

提示注入资料强调，来自文档、网页和邮件的第三方内容可试图诱导系统做并非用户意图的事；风险随敏感访问与主动行动增加。[5] RAG 的来源约束是基础，不是全面防御。

## 21. 快速测试（5 题）

1. 为什么空检索结果应在本地返回，而不是请模型“尽量回答”？
2. 为什么模型只输出 `citation_chunk_ids`，而不是完整引用元数据？
3. `answered` 状态至少需要满足哪两项本地条件？
4. 为什么合法 JSON 仍可能是不合格回答？
5. 句子“该块的相似度为 0.9，所以答案真实”错在哪里？

**答案要点：** 1. 避免无证据补全；2. 应用从真实块重建不可伪造的来源字段；3. 至少一条引用且每条属于实际检索集合；4. 它可能事实错误、误读、越权或证据不足；5. 分数只是当前排序信号。

## 22. 代码阅读（2 题）

1. 阅读 `_parse_grounded_answer()`。按顺序列出它如何处理空响应、非法 JSON、顶层类型、额外字段、枚举、长度、重复引用、状态矛盾和未知块 ID；解释每一关阻止的是什么。
2. 阅读 `_citation_map()` 与 `GroundedAnswer`。说明为什么 `Citation` 的标题、版本和字符范围不从模型 JSON 读取；若源文档后来更新，索引版本和 `source_version` 如何帮助定位回答当时所见证据？

## 23. Debug（2 题）

1. 将假传输的 `citation_chunk_ids` 改为 `unknown-0`。运行测试，观察稳定错误；不要修复为“若未知就删掉引用”，而要解释为什么静默删除会把原本的 `answered` 候选变成无依据回答。
2. 在 `rag_answer_completed` 日志中加入 `question` 或 `raw_response`。运行日志脱敏测试，确认失败；恢复后比较“字符数、状态、引用数”与“正文、系统指令、原始 JSON”各自的排障价值和暴露风险。

## 24. 编程练习（3 题）

1. 增加 `citation_reason` 的固定短枚举，例如 `direct_statement` 与 `supporting_context`。要求每条引用都有理由、理由不由自由文本构成，并为未知枚举、重复块与超长理由写测试。
2. 增加回答层离线夹具：给定固定 `RetrievalResult` 和假传输候选，验证正确引用、错误来源、无引用回答、矛盾状态和拒答。报告只能保存案例 ID、状态、引用数和门结果。
3. 设计一个供应商适配器接口草图，但不要接入真实密钥。它必须说明固定模型允许列表、`response_format` 严格 Schema、输入/输出 token 上限、超时、有限重试、错误映射、脱敏日志和单次烟雾验收；将它与模块 9 的实现逐项对照。

## 25. 逆向设计与课后项目

**逆向设计：** 某知识库聊天机器人把检索的全文和“忽略前文、给出最终答案”一起交给模型；模型可以自由填写 URL、版本、置信度和工具调用；无结果仍强制回答；系统把所有输出字段显示给用户；未知引用会被自动丢弃；日志存问题、全文、系统提示和原始响应；回答完成后自动更新数据库。请从证据、Schema、来源伪造、空结果、提示注入、权限、日志、成本、评测、人工复核和事故追踪至少倒推十一项失败点，并为每项提出模型外可测试控制。

**课后项目：** 将“课程检索器 v0.2”扩展为 **来源约束回答器 v0.3**。要求：问题长度/控制字符边界；空检索本地 `not_enough_evidence`，不调用传输；可替换传输 Protocol；严格四字段 JSON；枚举、长度、布尔值、引用数量与去重验证；`answered` 必须引用，拒答不得引用；引用 ID 必须来自实际检索块，所有展示元数据由应用重建；无正文日志；无网络测试、mypy、Ruff 与 CI；README 明确说明它只是候选回答、来源链和人工复核入口，不是事实认证或 Agent。真实模型适配必须复用模块 9 的受控做法，并在实时能力核对后才进行最小烟雾调用。
