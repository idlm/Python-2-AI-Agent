# 第 1.4 章：布尔值与任务状态

## 1. 本章目标

理解 `True`、`False` 与任务完成状态。

## 2. 为什么学习

程序必须根据事实作出分支；状态字段是后续工作流的基础。

## 3. Agent 中的作用

Agent 的工具是否成功、审批是否通过、任务是否结束都应以明确状态表示。

## 4. 前置知识

完成第 1.1–1.3 章。

## 5. 概念解释

布尔值只有 `True` 与 `False` 两种；`done` 字段表示任务是否完成。

## 6. 生活化比喻

门锁只有开与关；布尔值用于表达这种二元事实。

## 7. 原理分析

比较表达式产生布尔结果；后续 `if` 将依据它选择路径。

## 8. 最小示例

```python
task = {"title": "学习 Python", "done": False}
task["done"] = True
print(task["done"])
```

## 9. 逐行解释

字典保存任务；赋值更新状态；输出显示更新后的事实。

## 10. 常见错误

不要用字符串 `"False"` 代替布尔值 `False`。

## 11. Traceback 分析

访问不存在的 `done` 键会产生 `KeyError`，说明数据模型缺字段。

## 12. 错误案例

把“已完成”存成任意文本，导致不同步骤对状态作出不同解释。

## 13. 改进方案

统一使用 `done: bool`，在创建任务时提供默认值。

## 14. 工程实践

状态字段应有明确含义、创建位置和测试。

## 15. 性能优化

先保证状态正确；微小布尔判断无需优化。

## 16. 安全问题

权限、审批与删除确认不能只靠界面文字，必须使用受控状态与服务端验证。

## 17. 小项目

为任务增加完成切换，并输出完成/未完成标签。

## 18. 单元测试

测试新任务默认 `done` 为 `False`，更新后为 `True`。

## 19. 自测题

1. 布尔值有哪些？ 2. 为什么不用字符串状态？ 3. 状态如何影响工作流？ 4. 缺字段说明什么？ 5. 默认值为何重要？
