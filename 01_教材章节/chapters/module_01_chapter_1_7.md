# 第 1.7 章：数据结构——为任务选择合适容器

## 1. 本章目标
理解列表、字典、元组和集合的基本用途，并为任务管理器选择列表加字典的模型。

## 2. 为什么学习
多个任务需要集合保存；单个任务需要有名称的字段。

## 3. Agent 中的作用
消息列表、工具参数、状态字典和去重集合都是 Agent 的基本数据形状。

## 4. 前置知识
完成第 1.1–1.6 章。

## 5. 概念解释
列表按顺序保存多项；字典按键保存字段；元组适合固定序列；集合适合去重成员。

## 6. 生活化比喻
列表像待办队列，字典像任务卡片，集合像不重复的标签盒。

## 7. 原理分析
任务列表可写为 `tasks = [{"title": "学习", "done": False}]`；外层列表管理多项，内层字典描述每项。

## 8. 最小示例
```python
tasks = [{"title": "学习变量", "done": False}]
tasks.append({"title": "完成练习", "done": False})
print(tasks[0]["title"])
```

## 9. 逐行解释
列表保存字典；`append` 增加任务；双重索引先取任务再取标题。

## 10. 常见错误
不要用集合保存需要稳定顺序的任务；不要用列表位置代替有含义字段。

## 11. Traceback 分析
使用不存在的字典键会产生 `KeyError`；访问不存在的列表位置会产生 `IndexError`。

## 12. 错误案例
把任务标题和状态放在平行列表中，删除一项后可能发生错位。

## 13. 改进方案
把同一任务的字段放进一个字典，再用列表保存多条任务。

## 14. 工程实践
为字段制定一致键名，如 `title`、`priority`、`done`，并在创建时提供默认值。

## 15. 性能优化
先选正确模型；任务很少时可读性比微小容器性能更重要。

## 16. 安全问题
外部输入不能直接成为字典键或路径；需要验证允许字段与长度。

## 17. 小项目
实现一个包含两条任务的列表，并输出所有未完成标题。

## 18. 单元测试
测试添加任务后长度增加，且每条任务包含 `title` 与 `done`。
