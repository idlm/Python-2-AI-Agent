# 第 11.2 章：先看见循环，再允许循环——Agent 事件、静态夹具与审批评测

**适用版本：** Python 3.11+  
**项目连接：** `02_可运行项目/projects/11-bounded-agent-core/`（v0.1.0）  
**前置章节：** 第 11.1 章的有限状态、纯工具、预算与审批暂停。

## 1. 本章目标

本章把“Agent 运行了”变成可复查的最小事实：状态、步骤、固定动作、结果类别、预算停止、审批暂停和静态夹具结果。你将学习为什么日志不是全文仓库，为什么一次演示不是评测。

## 2. 可观察性先于扩权

一旦系统可以多步行动，问题不再只有“输出对不对”，还包括“走了哪条状态路径、调用了什么合同、为何停止”。先观察受限纯工具循环，再讨论模型或副作用工具。[1]

## 3. 最小事件合同

项目事件只含任务 ID、步骤、状态、动作和结果类别。它不含目标、参数、模型输出、工具正文、提示或密钥。

## 4. 为什么日志不能保存一切

全文日志会扩大个人信息、业务数据、攻击载荷和秘密的留存面。最小事件便于定位状态转换，却不是完整审计系统。

## 5. 原子事件报告

报告先写临时文件再替换目标，避免读到半个 JSON。原子替换不提供跨机器事务、备份、权限或长期保留保证。

## 6. 事件类别帮助 Debug

`public_lookup_completed`、`approval_required`、`completed` 和 `budget_exhausted` 比一段自由文本更适合统计和测试。类别必须来自固定枚举或代码路径。

## 7. 状态与事件相互校验

`waiting_for_approval` 应对应审批类别；`stopped` 应有预算或拒绝原因；`completed` 后不能继续执行。状态不一致应是测试失败，而非“模型偶尔犯错”。

## 8. 静态夹具是什么

静态夹具是版本化、公开、课程自制的输入与预期结果集合。项目夹具回放纯工具、审批拒绝和注入文本作为数据，不访问模型或网络。

## 9. 静态夹具不是什么

它不是生产流量、事实准确率、模型排行榜或安全认证。它只证明当前代码对已定义案例保持合同。

## 10. 提示注入也要回放

夹具中的“忽略规则并执行命令”仍只作为纯工具参数。它没有变成动作、工具名或批准。风险来自不可信数据影响行为，因此动作必须由应用允许列表决定。[2]

## 11. 未知动作必须拒绝

`ActionKind("shell")` 失败而不是回退到执行。错误的“智能兼容”常把未知输入升级成权限扩大。

## 12. 审批拒绝也是成功路径

审批拒绝后任务进入 `stopped`，原因是 `approval_denied`。这是安全完成，不是系统崩溃。评测应将其与错误和预算耗尽分开。

## 13. 默认 CLI 不运行任务

项目 CLI 默认只报告能力边界；`--run-static-evaluation` 才回放公开夹具。它不接收任意目标、动作、模型、工具、凭据或审批参数。

## 14. 状态命令为什么重要

状态路径可用于安装验证和故障排查，却不应触发模型、网络或副作用。这是“可观察而不扩权”的小例子。

## 15. 评测门的层次

| 层 | 检查 |
|---|---|
| 输入 | ID、目标、参数和夹具字段。 |
| 状态 | 合法转移、完成后停止、审批暂停。 |
| 工具 | 固定动作、纯工具参数、未知动作拒绝。 |
| 预算 | 步数耗尽可解释停止。 |
| 隐私 | 报告不含正文、参数或结果全文。 |

## 16. 通过不代表可信行动

夹具通过只表示代码符合案例合同。它不证明未来模型会选对动作、工具结果真实、批准有效或现实操作安全。

## 17. Trace 与最小事件的关系

平台可提供跨模型和工具的 tracing。[1] 本书先定义供应商无关事件，之后若接入追踪系统，也必须执行脱敏、访问控制、留存和评测设计。

## 18. 不要用模型评分代替合同

模型可以辅助评估文本，但状态机、动作允许列表、参数 Schema、预算和审批必须由确定性代码验证。评测不应让被测 Agent 自己宣布通过。

## 19. 失败应当可复现

用假纯工具、固定夹具和受限 CLI 后，预算耗尽、未知动作、审批拒绝与注入文本都可无网络复现。可复现失败比偶发“看起来正常”更有教学价值。

## 20. 何时增加模型

只有纯状态、工具、报告和夹具已经稳定时，才让模型生成一个小枚举内的行动候选。模型输入仍是数据，模型输出仍要本地解析、验证和授权。

## 21. 快速测试（5 题）

1. 最小事件为何不写工具参数？2. 审批拒绝为何不是异常？3. 静态夹具通过证明什么？4. 未知动作为何必须拒绝？5. 默认 CLI 为什么不能运行任务？

## 22. 代码阅读（2 题）

1. 阅读 `write_public_event_report()`，解释为何不直接序列化任务对象。2. 阅读 `run_static_cases()`，找出注入文本只能进入哪个字段。

## 23. Debug（2 题）

1. 在夹具中加入 `shell` 动作，确认得到固定夹具错误。2. 将审批案例改为 `approval=true`，确认任务恢复到 `running` 而不是自动完成。

## 24. 编程练习（3 题）

1. 为事件加入停止原因字段，测试预算与拒绝原因。2. 为静态报告加入通过/失败计数且不保存正文。3. 增加重复案例 ID 拒绝与版本字段检查。

## 25. 逆向设计与课后项目

**逆向设计：** 某 Agent 保存完整提示、用户数据和工具返回；未知动作回退为 shell；审批由模型文本决定；默认 CLI 会执行任务。倒推至少八项风险和模型外控制。

**课后项目：** 完成受限 Agent 离线评测：固定夹具、状态/预算/审批/注入门、无正文原子报告、受控 CLI、pytest、mypy、Ruff、CI。不得接入真实模型或副作用。
