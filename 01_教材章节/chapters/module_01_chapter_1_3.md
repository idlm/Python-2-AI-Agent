# 第 1.3 章：字符串、数字与可读输出

**项目连接：** 命令行任务管理器需要用字符串保存标题，用整数表示优先级，用可读文本呈现任务。

## 1. 本章目标

能够区分文本与数字，使用基础算术和格式化输出表达一条任务信息。

## 2. 为什么学习

用户输入通常是文本，业务规则常需要数字；混淆二者会导致计算、排序和显示错误。

## 3. Agent 中的作用

Agent 的工具参数、Token 统计、费用和检索分数都必须以正确类型保存与显示。

## 4. 前置知识

完成第 1.1–1.2 章。

## 5. 概念解释

`str` 表示文本，`int` 表示整数，`float` 表示小数。引号中的 `"3"` 是文本，不是整数 3。[1]

## 6. 生活化比喻

“第 3 号任务”中的 3 是标签文字；“3 个任务”中的 3 可参与计数。外观相同不代表用途相同。

## 7. 原理分析

`+` 对数字表示加法，对字符串表示拼接；f 字符串把值嵌入可读文本。类型决定操作含义。[1]

## 8. 最小示例

```python
title = "完成练习"
priority = 2
print(f"任务：{title}；优先级：{priority}")
print(priority + 1)
```

## 9. 逐行解释

第一行绑定字符串，第二行绑定整数；第三行格式化显示，第四行做数值加法。

## 10. 常见错误

`"2" + 1` 会产生 `TypeError`；不要用字符串拼接假装数值计算。

## 11. Traceback 分析

看到 `TypeError` 时，先检查运算符两边的值与 `type()` 输出，再决定转换规则。

## 12. 错误案例

将优先级保存为 `"10"` 后按文本排序，可能得到 1、10、2 的错误顺序。

## 13. 改进方案

在输入边界把合法文本转换为整数，并为非法文本保留明确错误路径。

## 14. 工程实践

内部数据使用正确类型，展示层再格式化；不要用显示文本代替结构化字段。

## 15. 性能优化

本章无需优化；先保证类型正确和输出可读。

## 16. 安全问题

用户文本可能含控制字符或敏感信息；日志显示时应限制长度并避免泄露。

## 17. 小项目

给任务增加 `priority` 数字字段，并输出“任务、优先级、完成状态”。

## 18. 单元测试

测试优先级为 2 时，格式化输出包含 `2`，而数值加 1 的结果为 3。

## 19. 自测题

1. `"3"` 与 `3` 的区别？ 2. f 字符串解决什么问题？ 3. 何时应转换类型？ 4. 排序为何依赖类型？ 5. `TypeError` 如何定位？

## 20. 代码阅读题
