# 第 2.5 章：文本分析工具——组合函数、测试与项目收束

## 1. 本章目标
将规范化、统计、报告和 CLI 组合为可运行项目。

## 2. 为什么学习
项目价值来自多个小函数按清晰接口协作。

## 3. Agent 中的作用
Agent 系统也是组合模型、工具、状态与评测的项目，不是单个函数。

## 4. 前置知识
完成第 2.1–2.4 章。

## 5. 概念解释
组合是让一个函数的返回值成为下一函数输入；集成测试验证组合后行为。

## 6. 生活化比喻
流水线每个工位只做一件事，交接规格确保成品正确。

## 7. 原理分析
`format_report` 调用 `analyze_text`，后者调用 `count_words`，后者调用 `normalize_text`；分层使错误可定位。

## 8. 最小示例
```python
from text_analyzer.core import format_report

print(format_report("a b"))
# 预期输出：字符数：3；词数：2；行数：1
```

这段代码要求先进入 `02_可运行项目/projects/02-text-analyzer/`，再用该项目的虚拟环境执行 `.venv/bin/python -m pip install --editable ".[dev]"`；若尚未安装，请先使用本章末尾的项目测试命令验证环境。实际兼容入口仍可使用 `02_可运行项目/projects/02-text-analyzer.py`，但新练习应优先使用安装后的标准包。

## 9. 逐行解释
顶层负责呈现；统计层负责数据；规范化层负责输入一致性。

## 10. 常见错误
不要在每层重复清洗；不要让 CLI 直接承担全部业务逻辑。

## 11. Traceback 分析
若报告层收到错误类型，沿调用链找最早未验证的边界。

## 12. 错误案例
CLI、统计和打印混在一处，无法对非交互函数写测试。

## 13. 改进方案
保持纯函数可独立测试，CLI 只负责输入和输出。

## 14. 工程实践
README、测试、文件路径、错误策略与非目标必须同步维护。

## 15. 性能优化
统计一次，格式化一次；避免重复遍历大文本。

## 16. 安全问题
文件输入加入前先定义允许路径、大小上限、编码和日志脱敏。

## 17. 小项目
为文本分析工具增加单独的 `--help` 设计草案和文件输入验收标准。

## 18. 单元测试
运行 `python3 -m unittest 05_教学测试/tests/module_02/test_text_analyzer.py -v`，当前应通过三项测试。
