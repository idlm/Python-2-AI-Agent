# 第 0.4 章：学习日志、问题清单与可复现练习环境

**所属模块：** 模块 0·学习准备与逆向思维  
**代码版本：** Python 3.11+  
**本章示例：** `examples/module_00/study_record.py`  
**本章测试：** `05_教学测试/tests/module_00/test_study_record.py`

> **本章核心观点：** 学习不是一次次“重新开始”。每一次运行、困惑、错误和修复都应留下足以让未来的你或他人复现的证据。

## 1. 本章目标

完成本章后，你能够建立一份学习日志和问题清单；能够记录运行命令、解释器版本、当前目录、预期与实际输出；能够创建一个项目专属虚拟环境，并理解它为何能减少依赖冲突；能够将“我卡住了”转化为下一步可执行的问题。

| 可观察成果 | 完成标准 |
|---|---|
| 学习日志 | 每次练习均有日期、目标、命令、结果与下一步。 |
| 问题清单 | 每个问题有现象、最小复现、假设与验证状态。 |
| 环境快照 | 可说明 Python 版本、解释器路径、CWD 与依赖来源。 |
| 虚拟环境 | 能为项目创建 `.venv`，并确认激活后解释器改变。 |

## 2. 为什么学习

没有记录的学习会产生一种错觉：你以为自己一直在前进，实际上同一个安装问题、路径问题或概念误解可能反复出现。几周后你看到一段旧代码，往往记不起它为何能运行、当时用哪个 Python、输入是什么、改动解决了什么。这不是记忆力不好，而是软件工作本来就需要外部化的证据系统。

虚拟环境是这种证据系统的一部分。Python 官方文档说明，`venv` 可以创建轻量、独立的 Python 环境；使用哪个 Python 命令创建，环境就基于该版本。激活环境会改变 Shell 的环境，使 `python` 指向该环境的解释器。[1] 它并不解决所有问题，但能让“这个项目依赖什么、由哪个解释器运行”变得更清楚。

## 3. Agent 中的作用

Agent 平台同样需要“学习日志”，只不过它们叫作配置、运行记录、追迹、评测集、部署清单和事故复盘。没有这些记录，团队无法回答：这次回答为何变差？模型版本是否变化？使用了哪份知识库？工具调用是否超时？错误是否可以重放？

你今天维护的学习日志，就是未来 MLOps 与生产运维的缩小版。它把一次偶然成功变成可重复流程，把一次失败变成可检索知识，把模糊感受变成可验证假设。

## 4. 前置知识

你需要完成第 0.1–0.3 章，能够运行 Python、理解当前工作目录，并保留完整 Traceback。本章的 `.venv`、`pip`、依赖清单将在模块 5 详细讨论；现在只建立正确心智模型与安全工作流：先确认解释器，再创建环境，再记录命令，再安装最少依赖。

不要将 `.venv` 与 `.env` 混为一谈。`.venv` 通常是放置虚拟环境文件的目录；`.env` 常被工具用来保存环境变量，而环境变量中可能含有密钥。两者都不应随意复制到公开仓库，尤其不能提交真实 Token、密码或个人路径。

## 5. 概念解释

**学习日志**记录你做了什么和学到了什么；**问题清单**记录尚未解决或需要验证的问题；**可复现环境**使他人或未来的你能以相同版本、命令和依赖重新运行同一练习。它们共同构成学习的“外部记忆”。

**虚拟环境（Virtual Environment）**是项目专属的一组 Python 解释器和包安装位置。不同项目可以拥有不同版本的第三方包，避免一个练习的安装影响另一个练习。虚拟环境不是容器，也不是远程服务器；它首先是本机上的目录和一组路径设置。

| 记录项 | 应记录什么 | 为什么需要 |
|---|---|---|
| 目标 | 本次要验证的一个具体能力。 | 防止把“学习 Python”写成无边界任务。 |
| 命令 | 从哪个目录执行的完整命令。 | 让路径与解释器问题可复现。 |
| 预期 / 实际 | 你以为会发生什么，实际发生什么。 | 使错误成为可比较差异。 |
| 环境 | Python 版本、解释器路径、CWD、依赖。 | 识别“同代码不同环境”。 |
| 下一步 | 一个能在短时间执行的验证动作。 | 防止问题清单变成焦虑清单。 |

## 6. 生活化比喻

实验室里的实验记录本不会只写“今天做实验”。它会写试剂批次、温度、步骤、现象、失败与下一次调整。否则，即使得到好结果也无法判断它是规律还是偶然。学习日志就是你的编程实验记录本。

虚拟环境像给每个实验准备独立工作台：A 实验桌上的材料不会散落到 B 实验桌。它不会自动让实验成功，但能减少“上次安装的东西为什么影响这次”的混乱。比喻的边界是：真正的隔离程度有限，系统级依赖、环境变量和网络仍可能影响程序；因此还要记录版本和命令。

## 7. 原理分析

可复现练习环境可以按四层保存：

```text
代码：运行的是哪一份文件？
解释器：哪一个 Python 在执行？
依赖：它从哪里加载包、包版本是什么？
命令与输入：在什么目录，以什么参数运行？
```

若四层中任一层不明确，“在我电脑上能运行”就不可验证。创建虚拟环境的典型命令是 `python -m venv .venv`；官方文档说明它会创建包含解释器与支持文件的目录，并将 `.venv` 列为常用名称。[1] 关键并不是记住命令，而是理解 `python -m venv` 开头的 `python` 决定了环境基于哪个 Python 版本。

## 8. 最小示例

文件 `examples/module_00/study_record.py` 用结构化字段生成一条最小学习记录：

```python
"""第 0.4 章：生成最小学习记录。支持 Python 3.11+。"""

from pathlib import Path
import sys


def build_record(topic: str, question: str) -> dict[str, str]:
    """返回一条可复现学习记录所需的最小字段。"""
    return {
        "topic": topic,
        "question": question,
        "python_version": f"{sys.version_info.major}.{sys.version_info.minor}",
        "working_directory": str(Path.cwd()),
        "next_action": "写出一个最小示例，并记录预期输出。",
    }


def format_record(record: dict[str, str]) -> str:
    """将学习记录格式化为 Markdown 风格的可读文本。"""
    return "\n".join(f"- {key}: {value}" for key, value in record.items())


def main() -> None:
    record = build_record("Traceback 阅读", "为什么 int('猫') 会失败？")
    print(format_record(record))


if __name__ == "__main__":
    main()
```

在项目根目录运行：

```bash
python3 examples/module_00/study_record.py
```

预期输出包含主题、问题、Python 主次版本、工作目录和下一步。路径与版本会随你的环境变化，这不是测试失败；相反，它证明记录捕捉到了本次实际运行的环境。

接着创建虚拟环境。Linux/macOS 的 Bash 示例：

```bash
python3 -m venv .venv
source .venv/bin/activate
python --version
python -c "import sys; print(sys.executable)"
deactivate
```

Windows PowerShell 常用激活命令为 `.venv\Scripts\Activate.ps1`；Windows 命令提示符常用 `.venv\Scripts\activate.bat`。如果组织策略限制脚本执行，不要绕过安全策略；应先理解提示内容并遵循本机或组织的受控配置。

## 9. 逐行解释

| 代码位置 | 作用 | 工程含义 |
|---|---|---|
| `Path.cwd()` | 读取这次运行的工作目录。 | 将路径上下文写进记录。 |
| `sys.version_info` | 提取结构化版本信息。 | 版本是可比较事实，不是模糊印象。 |
| `build_record` | 将主题、问题与环境聚合成字典。 | 记录应有固定字段，便于回看。 |
| `format_record` | 将数据转为人可读文本。 | 数据保存和呈现可以分离。 |
| `next_action` | 规定下一次最小实验。 | 让问题清单推动行动而非堆积。 |

## 10. 常见错误

| 现象 | 常见原因 | 改进动作 |
|---|---|---|
| 激活后仍显示系统 Python | 激活命令不适合当前 Shell，或命令在另一个终端执行。 | 运行 `python -c "import sys; print(sys.executable)"` 确认事实。 |
| `.venv` 被提交到仓库 | 不理解其是机器生成目录。 | 将 `.venv/` 加入 `.gitignore`；保留依赖清单而不是环境目录。 |
| 日志只有“今天学了函数” | 目标、输入、输出和问题不可复现。 | 使用本章五字段模板。 |
| 问题无限积累 | 每条问题没有最小下一步和状态。 | 标注“待验证、已复现、已解决、已搁置”。 |

## 11. Traceback 分析

如果你在尚未创建 `.venv` 时运行：

```bash
source .venv/bin/activate
```

Bash 会提示找不到该文件。这不是 Python Traceback，而是 Shell 在文件层面找不到激活脚本。排查顺序应是：`pwd` 确认当前位置，`ls -a` 确认 `.venv` 是否存在，再确认是否已执行 `python3 -m venv .venv`。不要用“安装更多包”解决一个目录不存在的问题。

若 `python -m venv .venv` 本身失败，则记录完整输出、Python 版本和系统信息；某些系统可能缺少对应的 venv 组件，需要使用受信任的系统包管理方式安装。不要从不可信来源下载并执行所谓“一键修复脚本”。

## 12. 错误案例

错误学习记录示例：

```text
今天：装了很多包，代码还是不能跑。
解决：重装了一遍。
```

它没有说明哪个代码、哪个命令、哪个解释器、什么错误、安装了哪些包，也无法判断“重装”是否真正解决问题。更危险的是，随意全局安装会让其他项目的依赖发生变化，造成新的不可解释问题。

## 13. 改进方案

使用如下问题模板：

```text
标题：运行哪个命令时出现什么现象？
预期：我认为应该看到什么？
实际：完整输出或 Traceback 是什么？
环境：Python 版本、解释器路径、CWD、依赖版本。
最小复现：删除无关步骤后，最短失败过程是什么？
假设：我目前认为哪一层可能有问题？
下一步：只验证哪一项？
状态：待验证 / 已复现 / 已解决 / 已搁置。
```

每次只让下一步验证一个假设。例如不要同时升级 Python、重装包、移动目录和改代码；先确认当前解释器是否在 `.venv` 中，再决定是否需要安装任何依赖。

## 14. 工程实践

每个项目从第一天起至少包含：`README.md`、源代码目录、测试目录、`.gitignore`、依赖说明和日志或问题记录。现在不必一次建立复杂工程模板，但要保证最小结构稳定。建议在日志中使用相对路径与项目提交版本，避免把个人桌面路径和真实密钥写入共享记录。

当开始使用第三方包时，记录安装命令、包名、版本和原因。将来我们会使用锁定文件和自动化环境构建；现在先建立“任何依赖都必须有来源和用途”的原则。

## 15. 性能优化

记录系统的性能目标是降低重复劳动。一个 30 秒能填写的模板，应优于一个需要维护十个页面的华丽笔记系统。问题清单应按“阻断当前任务”“本周可验证”“以后再研究”分类，优先清除阻断项。随着项目发展，再把日志接入结构化观测与搜索，而不是一开始就构建复杂知识管理工具。

## 16. 安全问题

日志、`.env`、终端历史和 Traceback 都可能泄露密钥、内部 URL、用户名或客户数据。提交或分享前，应检查并替换 Token、Cookie、密码、私有路径和真实文档内容。虚拟环境目录可能很大且含有第三方代码，不应被当作项目源代码提交；而依赖名称与版本需要保存，才能重建环境。

未来 Agent 服务的配置尤其要分离：代码定义变量名和合法格式，运行环境注入实际密钥，日志只记录是否成功读取而不打印密钥本身。

## 17. 小项目：个人可复现实验台

为当前教材根目录创建 `learning_log.md` 与 `issues.md`。在前者记录本章环境快照、创建 `.venv` 的命令和运行示例的输出摘要；在后者至少记录一个真实或故意制造的路径/输入问题，并按本章模板写出复现和修复。项目验收不是日志漂亮，而是隔一天后你仍能按文字重新运行。

## 18. 单元测试

将以下测试保存为 `05_教学测试/tests/module_00/test_study_record.py`：

```python
import unittest

from examples.module_00.study_record import build_record, format_record


class StudyRecordTests(unittest.TestCase):
    def test_record_contains_required_fields(self) -> None:
        record = build_record("环境", "Python 在哪里运行？")
        self.assertEqual(record["topic"], "环境")
        self.assertIn("python_version", record)
        self.assertIn("working_directory", record)

    def test_formatted_record_contains_topic(self) -> None:
        record = build_record("日志", "如何记录问题？")
        self.assertIn("- topic: 日志", format_record(record))


if __name__ == "__main__":
    unittest.main()
```

## 25. 逆向设计与课后项目

**逆向设计：** 假设一个初学者项目在 **学习日志、问题清单与可复现练习环境** 上失败：输入不可复现、状态不清、错误无法定位、数据被静默覆盖或结果难以验证。倒推至少五项缺失的规则、测试、日志、命名或操作边界，并按“先阻止什么风险”排序。
