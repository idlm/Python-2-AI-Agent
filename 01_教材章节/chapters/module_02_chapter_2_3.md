# 第 2.3 章：作用域与闭包——名称在何处有效

## 1. 本章目标
理解局部名称、外层名称与闭包如何保存函数创建时的上下文。

## 2. 为什么学习
函数拆解后，必须知道数据在何处可见，才能避免意外依赖全局状态。

## 3. Agent 中的作用
工具配置、会话状态和回调函数若捕获错误上下文，会导致跨用户或跨任务污染。

## 4. 前置知识
完成第 2.1–2.2 章。

## 5. 概念解释
函数内创建的名称通常是局部名称；闭包是内部函数保留并使用外层函数名称的能力。

## 6. 生活化比喻
局部名称像会议室白板；闭包像把会议摘要装进信封后带走。

## 7. 原理分析
调用函数时创建局部作用域；函数返回后局部名称通常不可直接访问。内部函数若引用外层名称，闭包可保留该引用。

## 8. 最小示例
```python
def prefixer(prefix: str):
    def apply(text: str) -> str:
        return f"{prefix}{text}"
    return apply
add_task = prefixer("任务：")
print(add_task("学习作用域"))
```

## 9. 逐行解释
外层函数接收前缀；内部函数使用 `prefix`；返回内部函数后，`add_task` 仍保留前缀上下文。

## 10. 常见错误
不要在函数中无意修改全局名称；不要假设局部变量能在函数外访问。

## 11. Traceback 分析
函数外访问局部名称会产生 `NameError`，表示名称不在当前作用域。

## 12. 错误案例
多个任务共享一个全局 `current_user`，并发处理时发生用户上下文串扰。

## 13. 改进方案
显式传递参数或将状态封装为对象；闭包只捕获必要且不会泄露的上下文。

## 14. 工程实践
避免可变全局状态；函数签名应揭示其数据依赖。

## 15. 性能优化
闭包用于清晰抽象，而非替代大规模缓存；先测量实际瓶颈。

## 16. 安全问题
闭包可能长期保留密钥或私人数据；最小化捕获范围并避免日志打印闭包内部状态。

## 17. 小项目
编写 `make_counter()`，返回一个每次调用增加计数的函数，并说明它保存了什么状态。

## 18. 单元测试
测试两个不同计数器互不影响；测试函数外无法直接访问其局部名称。
