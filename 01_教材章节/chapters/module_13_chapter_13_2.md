# 第 13.2 章：消息不是聊天记录——委派 Schema、预算、去重与故障传播

**适用版本：** Python 3.11+  
**前置章节：** 第 13.1 章的任务分割、角色和权限不扩散。  
**本章边界：** 只设计纯数据消息与离线状态机；不启动并发模型调用、队列、网络、数据库或真实工具。

## 1. 本章目标

本章将多 Agent 协作拆成可验证消息合同：如何声明委派、如何等待和汇总、如何限制预算、如何处理重复、失败和取消，而不把自由文本当作控制面。

## 2. 消息为什么必须结构化

自由文本容易遗漏角色、资源、预算、输出格式和责任。结构化消息让应用可在模型外拒绝未知字段、非法角色、越权工具和不匹配的父任务。[1]

## 3. 最小委派请求

一个请求至少需要：委派 ID、父任务 ID、角色、任务摘要、输入引用、允许工具集合、步骤/工具预算、截止条件、输出 Schema 版本和状态。每个字段都必须有范围。

## 4. 任务摘要不是原始上下文

摘要是经过应用选择的最小目标描述，不是完整用户对话、系统提示、密钥或其他 Agent 的隐私正文。需要更多数据时，传受控引用并单独授权读取。

## 5. 输入引用而非复制

使用文档 ID、块 ID、版本、范围或公开夹具 ID 表示输入。引用可帮助追踪和去重，也使访问控制集中在读取点，而不是复制到所有 worker 的上下文。

## 6. 角色允许工具集合

每条委派显式携带或引用受角色约束的只读工具集合。worker 不能通过输出申请新工具名；协调者也不能把调用方所有工具默认下放。

## 7. 预算是多层的

至少区分总体 worker 数、当前并发数、每 worker 步骤数、工具调用数、总时间和总成本。一个预算用尽不应悄悄从另一个预算借用。

## 8. 并发上限保护什么

并发上限防止同时创建过多工作、压垮共享资源或失去观察能力。官方多 Agent 文档也将最大并发子 Agent 视为配置项，而非无限派生许可。[1]

## 9. 委派状态机

最小状态可为 `queued`、`running`、`completed`、`failed`、`cancelled`、`timed_out` 与 `rejected`。迁移由协调者和受控运行时管理，不允许 worker 自由写任意字符串。

## 10. 完成不等于可汇总

`completed` 只表示 worker 给出了符合输出 Schema 的结果类别；协调者还要检查角色、输入版本、结果引用、预算、重复和冲突，才可进入汇总。

## 11. 失败要有类别

非法委派、权限拒绝、预算耗尽、超时、取消、暂时不可用、输出 Schema 失败和结果未知应分开。这样协调者才知道是停止、重试、降级还是人工复核。

## 12. 重试不是重新委派

重试同一受控工作需要稳定委派 ID、尝试次数、条件和幂等语义。重新委派应创建明确新 ID，并记录与旧工作关系，避免把重复执行伪装为一次工作。

## 13. 去重键怎么设计

可用父任务、角色、输入引用版本和受控任务摘要生成去重键。键不应包含秘密或全文；相同键应拒绝、复用或等待已有工作，语义必须明确。

## 14. 并发结果的顺序

并发完成顺序不稳定。汇总应按稳定委派 ID 或预定义排序合并，不能依赖“谁先返回”来决定权重、权限或最终结论。

## 15. 冲突不是投票

两个 worker 不同结果可能来自版本不同、范围不同、错误或不确定性。协调者应保留冲突类别、请求补证或人工复核，而不是简单多数投票宣布事实。

## 16. 部分结果的诚实表达

如果一个独立 worker 失败而其他工作成功，结果应明确哪些范围完成、哪些缺失以及为何缺失。不要因为部分产出可用就声称完整覆盖。

## 17. 取消传播

父任务取消后，排队工作不可启动，运行中工作应收到取消，并在有限时间内返回最终类别。取消不是删除证据，也不保证远端副作用已撤销。

## 18. 超时与结果未知

超时只说明等待超出预算。若 worker 或工具可能仍在运行，状态应为 `timed_out` 或 `outcome_unknown`，并交给查询或人工处置，不自动重复。

## 19. 汇总者的最小权限

汇总者通常只需读取结构化 worker 结果和公开引用，不需要直接访问所有底层工具。把权限集中在“聪明的总控”会扩大泄露和误操作面。

## 20. 离线评测重点

静态夹具应覆盖未知角色、重复委派、超并发、预算耗尽、越权工具、消息额外字段、输入版本冲突、超时、取消和部分失败，并断言未执行真实工具。

## 21. 快速测试（5 题）

1. 为什么任务摘要不应是完整聊天？2. 哪些预算需要分开？3. 为什么完成不等于可汇总？4. 重试和重新委派有什么不同？5. 超时为何可能产生结果未知？

## 22. 代码阅读（2 题）

1. 为一个委派对象列出应进入去重键的字段。2. 把自由文本“让三个 worker 查一下”改为字段闭集请求。

## 23. Debug（2 题）

1. 两个并发 worker 先后返回不同版本结果，说明汇总如何稳定排序并报告冲突。2. 父任务取消后一个 worker 继续运行，指出取消传播合同缺失点。

## 24. 编程练习（3 题）

1. 定义 `DelegationStatus` 枚举和合法迁移表。2. 实现纯函数生成不含正文的去重键。3. 写静态夹具测试越权工具和超并发拒绝。

## 25. 逆向设计与课后项目

**逆向设计：** 一个系统把完整聊天复制给所有 worker，让 worker 自选工具和状态，按最快返回结果汇总，超时后直接重复，取消后丢弃记录。倒推至少十项 Schema、权限、预算、排序、重放和审计控制缺失。

**课后项目：** 设计一套两角色委派消息协议：请求/结果 Schema、状态机、去重键、并发/预算规则、取消/超时语义、稳定汇总排序、冲突与部分失败报告、十条静态夹具。禁止真实并发和工具调用。
