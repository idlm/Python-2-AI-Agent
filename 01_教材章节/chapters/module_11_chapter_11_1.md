# 第 11.1 章：Agent 不是“会自己做事”——状态、工具、预算与审批合同

**适用版本：** Python 3.11+  
**项目连接：** `02_可运行项目/projects/11-bounded-agent-core/`（v0.1.0）  
**前置章节：** 模块 8 的状态机；模块 9 的受控模型输出；模块 10 的不可信数据、来源与评测。

## 1. 本章目标

本章建立第一个无框架 Agent 的可检查定义：任务状态、固定动作、纯工具、步骤预算、审批暂停、最小事件和受控停止。读者完成后应能解释：模型提出下一步，不等于系统可以执行下一步。

## 2. 先区分 workflow 与 Agent

工作流由代码预先规定路径；Agent 允许模型在受控状态和工具集合中动态选择过程。[1] 两者都需要输入、状态、错误、预算、日志和评测。先实现 workflow 和状态机，再增加有限选择，比先安装框架更容易审计。

## 3. 为什么不从框架开始

框架能隐藏循环、工具调用和记忆细节。隐藏不等于不存在。官方资料建议先采用简单、可组合模式，仅在复杂性确有可测量价值时增加 Agentic 系统。[3]

## 4. 最小 Agent 的六个部件

| 部件 | 最小职责 | 不负责 |
|---|---|---|
| 任务 | 保存受控目标与 ID。 | 保存任意用户资料。 |
| 状态 | 限制生命周期。 | 自动持久化。 |
| 动作 | 从小枚举选择候选。 | 授予权限。 |
| 工具 | 执行固定合同。 | 执行任意文本。 |
| 预算 | 限制步骤。 | 保证质量。 |
| 事件 | 记录最小摘要。 | 保存正文或秘密。 |

## 5. 有限状态是第一道边界

项目使用 `ready`、`running`、`waiting_for_approval`、`completed`、`stopped` 和 `failed`。每个状态都只有明确入口和出口。状态不是字符串标签，而是外部行为的合同。

## 6. 任务先启动，再执行

```python
task = agent.start(AgentTask(task_id="task-1", goal="公开事实查询"))
```

只有 `ready` 任务能启动。重复启动、已停止任务继续运行或在等待审批时调用工具都受控失败。

## 7. 动作是候选，不是命令

`ActionKind` 目前只允许 `lookup_public_fact`、`complete` 和 `request_approval`。未来模型若说“运行 shell”或“删除文件”，该文本不在枚举中，不能进入执行路径。

## 8. 工具必须有小合同

首个工具是纯函数：同一输入返回结果，不写文件、不发网络、不改数据库。工具参数为 1–120 字符非空字符串。纯工具不是安全万能药，但能让第一轮状态、预算和事件测试不涉及现实副作用。

## 9. 不可信文本仍是数据

提示注入可来自文档、网页、邮件或用户输入，并试图改变行为或诱导下游工具。[2] 因此外部文本不能变成动作、工具名、Python callable 或审批结论；只能作为受控数据进入明确字段。

## 10. 步骤预算让循环会停止

项目最多执行五步。预算耗尽时任务进入 `stopped`，停止原因是 `step_budget_exhausted`。无限“再试一次”会扩大成本、延迟和复合错误。

## 11. 完成也必须是状态转换

`complete` 不是 `print("done")`，而是由 `running` 转为 `completed` 并产生事件。调用者可据此展示结果、写评测或拒绝后续步骤。

## 12. 审批是暂停，不是文字

`request_approval` 只把任务转为 `waiting_for_approval`，不执行任何操作。只有应用调用 `approve(..., approved=True)` 才恢复；拒绝则停止。模型说“用户同意”不构成批准。

## 13. 最小事件记录什么

事件记录任务 ID、步骤编号、状态、固定动作和结果类别。例如 `public_lookup_completed`。不记录目标正文、工具参数、系统提示、模型原文或密钥。

## 14. 事件为什么不是审计全部

最小事件帮助定位“哪一步、何种状态、何种结果”。生产审计还要定义访问控制、留存、完整性、时钟、事件关联和敏感数据策略；本项目不假装具备这些能力。

## 15. 预算、超时与 token 不同

步骤预算限制状态机循环次数；超时限制等待；token 预算限制模型文本；成本预算限制资源。四者应分别设计，不能用一个数字替代全部控制。

## 16. 纯工具返回不是事实认证

即使纯工具返回内容，也可能过时、不完整或不适用。工具结果是环境反馈，不是自动批准。模块 10 的来源、拒答和人工复核原则仍适用。

## 17. 失败要可解释

非法状态、空参数、未知动作和预算耗尽均返回稳定合同错误或停止理由；不将异常原文、用户正文或秘密直接写入日志。失败路径同样需要测试。

## 18. Agent 不是自动执行授权

OpenAI 的安全资料建议用结构化输出约束节点间数据流、保留工具审批，并避免让不可信数据直接驱动行为。[2] 本章项目不接入网络、文件、SQL、shell、支付或账户工具。

## 19. 何时需要真正 Agent

当步骤数量与顺序无法由可靠代码预先决定、环境反馈必须改变下一步且任务有可测量成功条件时，才考虑有限 Agent。若固定路径足够，workflow 更可预测、更便宜、更易测。[3]

## 20. 框架放在原理之后

OpenAI 区分应用自己管理循环和 SDK 管理循环。[1] 学会本章状态机后，读者才有能力检查框架的 run、tool、approval、state 和 trace 是否满足自己的合同。

## 21. 快速测试（5 题）

1. workflow 与 Agent 的关键差异是什么？ 2. 为什么动作候选不是授权？ 3. 步骤预算解决什么问题？ 4. 审批暂停与模型输出“approved”有什么不同？ 5. 纯工具为什么仍不等于事实认证？

**答案要点：** 代码路径与动态选择不同；权限在模型外；预算保证停止；批准是应用状态转换；工具结果仍需来源和复核。

## 22. 代码阅读（2 题）

1. 阅读 `BoundedAgent.step()`，列出预算、审批、完成和纯工具分支的状态变化。2. 阅读 `_event()`，解释为何只保留结果类别而不保留工具参数。

## 23. Debug（2 题）

1. 对 `stopped` 任务调用 `step()`，观察稳定错误。2. 将纯工具参数设为空，确认工具不被调用，并解释为什么“自动补默认查询”会扩大权限。

## 24. 编程练习（3 题）

1. 增加任务 ID 格式验证并测试重复/非法 ID。2. 增加每任务工具调用上限，与步骤预算分开测试。3. 为事件添加受控持续化替身，报告只保存计数和类别。

## 25. 逆向设计与课后项目

**逆向设计：** 一个机器人接受模型任意 Python 代码、没有步骤上限、把网页文本当系统指令、模型自行批准退款、日志保存全部提示和密钥。至少倒推八项失败点，并提出模型外控制。

**课后项目：** 将项目 11 扩展为受限 Agent v0.1：有限状态、固定纯工具、预算、审批暂停、事件脱敏、离线假规划器、受控失败、pytest、mypy、Ruff、CI。不得接入框架、真实模型或副作用工具。
