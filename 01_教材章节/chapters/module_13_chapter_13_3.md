# 第 13.3 章：汇总不是复制粘贴——冲突、证据、追踪与人工复核

**适用版本：** Python 3.11+  
**前置章节：** 第 13.1–13.2 章的任务分割、消息 Schema、预算和故障传播。  
**本章边界：** 只评估结构化 worker 结果；不访问真实来源、不调用模型或工具。

## 1. 本章目标

本章说明协调者如何安全汇总多个 worker 的结果。重点是区分完成、支持、冲突和缺失，并把追踪和人工复核限制在最小必要数据。

## 2. 汇总者不是更高权限的 worker

汇总者负责检查和组合受控结果，而不是获得所有底层工具、全部原始上下文或修改 worker 历史。最小权限同样适用于协调层。

## 3. 结果 Schema 的最小字段

结果至少应含委派 ID、父任务 ID、角色、输入引用版本、状态、结果类别、受控引用 ID、计数和错误/停止类别。不要默认保存自然语言思考、完整工具返回或提示。

## 4. 引用不等于事实认证

worker 返回的来源引用只说明它声称依赖某个受控输入。汇总者还需检查引用存在、版本匹配、范围允许和支持关系；引用本身不自动证明事实正确。

## 5. 先检查身份与范围

汇总前验证委派 ID、父任务、角色、输入版本和输出 Schema。来自错误父任务、过期输入或越权角色的结果必须拒绝，即使文字看起来有用。

## 6. 稳定排序的意义

并发完成顺序不可预测。按预定义角色优先级、委派 ID 或输入顺序排序，使报告、测试和人工复核可重复；不要让网络速度决定最终结论。

## 7. 重复结果如何处理

相同去重键的 worker 结果应被识别：可保留一个、标记重复或作为对照，但不能重复计入覆盖率、成本或“多数意见”。

## 8. 冲突类别

将冲突至少分为：输入版本不同、范围不同、来源不一致、状态不一致、结论不一致和信息不足。分类比把两段文本交给模型“选一个”更可审查。

## 9. 冲突不是多数投票

三个相同错误不会成为正确答案。高风险或事实型冲突应回到受控来源、补证任务或人工复核；投票只可能是某些明确主观任务的受限策略。

## 10. 缺失是第一类结果

worker 超时、拒绝、预算耗尽、无证据或未返回，必须进入汇总报告。忽略缺失会让最终输出把“不知道”伪装成“已覆盖”。

## 11. 部分成功如何表述

报告应显式写出完成范围、未完成范围、失败类别和对最终结论的影响。协调者可以降级结果或请求人工复核，但不能静默删掉失败。

## 12. 最小追踪事件

事件可保存委派 ID、父 ID、角色、状态转换、预算计数、结果类别和耗时区间。它们足以排查协调问题，通常不需要任务正文、提示、原始响应或工具返回。

## 13. 追踪关联和隐私

关联 ID 让你追溯同一委派链，却不应成为跨系统跟踪个人的永久标识。定义访问角色、保留期限、删除流程和报告脱敏规则。

## 14. 评测不只看最终答案

多 Agent 评测还要测：是否重复委派、是否越权、是否超预算、是否稳定汇总、是否正确暴露部分失败、是否把注入文本当数据。[1] [2]

## 15. 过程指标需谨慎

worker 数、并发、延迟、成本、成功率和冲突率有助诊断，却不是通用质量分数。指标应分任务类型和版本解释，避免用总平均数掩盖高风险失败。

## 16. 人工复核的触发条件

来源冲突、低证据、预算耗尽、结果未知、权限拒绝、输出超出声明范围、政策变化或高影响建议都可触发复核。规则应在运行前定义。

## 17. 复核者看到什么

最小复核包包括案例/委派 ID、版本、角色、状态、受控引用、冲突类别、计数、决定和理由类别。需要正文时按最小权限、按需访问，而非默认广泛展示。

## 18. 复核不是免责按钮

人工批准也可能误判。系统仍需输入验证、权限、审批范围、日志、双人复核（适用时）、可撤回动作和事故处置；责任不能被一个按钮转移。

## 19. 提示注入跨 Agent 传播

一个 worker 若转发未经处理的网页文字，另一个 worker 或汇总者可能把其中指令当任务。应提取结构化字段、标记来源、限制转发并在每层重新验证。[2]

## 20. 发布前的汇总门禁

在真实模型或工具前，静态夹具应证明：合法结果可汇总、重复被标记、冲突被暴露、缺失不消失、越权被拒绝、报告无正文，且所有失败有稳定类别。

## 21. 快速测试（5 题）

1. 为什么汇总者不应拥有全部工具？2. 引用为何不等于事实认证？3. 稳定排序解决什么问题？4. 为什么冲突不宜多数投票？5. 哪些情况需人工复核？

## 22. 代码阅读（2 题）

1. 为两个 worker 结果写出稳定排序键。2. 将一个完整工具响应缩减为最小追踪事件字段。

## 23. Debug（2 题）

1. 一个 worker 结果的父任务 ID 错误，说明为何必须在汇总前拒绝。2. 两个结果引用同一来源却结论相反，列出冲突分类与下一步。

## 24. 编程练习（3 题）

1. 定义 `WorkerResult` 与 `ConflictCategory` 枚举。2. 实现纯函数标记重复和稳定排序。3. 写无正文汇总报告并测试不落盘参数或结果正文。

## 25. 逆向设计与课后项目

**逆向设计：** 一个协调者拼接所有 worker 文本、按最快返回排序、忽略超时、把多数意见当事实，并保存完整 trace。倒推至少十项汇总、证据、隐私、评测和复核控制缺失。

**课后项目：** 设计三 worker 结果汇总器：结果 Schema、身份/版本检查、稳定排序、去重、冲突/缺失类别、人工复核触发、最小事件、无正文报告和静态夹具。禁止模型和真实来源。
