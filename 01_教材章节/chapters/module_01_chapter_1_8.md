# 第 1.8 章：输入输出——让任务管理器与用户对话

## 1. 本章目标
使用 `input()` 接收文本，用 `print()` 输出任务结果，并理解输入验证边界。

## 2. 为什么学习
程序只有接收用户意图并返回结果，才从静态脚本变成可使用工具。

## 3. Agent 中的作用
Agent 接收消息、工具参数和 API 请求，并以结构化输出回应；所有输入都应被验证。

## 4. 前置知识
完成第 1.1–1.7 章。

## 5. 概念解释
`input()` 返回字符串；`print()` 显示文本。数值输入需要先验证再转换。

## 6. 生活化比喻
输入像用户填写表单，输出像系统回执；表单不完整时不能假装数据有效。

## 7. 原理分析
命令行程序读取标准输入，处理后写入标准输出；测试时可用固定输入替代人工键盘。

## 8. 最小示例
```python
title = input("任务标题：")
print(f"已创建任务：{title}")
```

## 9. 逐行解释
第一行等待并返回字符串；第二行格式化回执。

## 10. 常见错误
`input()` 得到的 `"2"` 不是整数 2；空标题不能直接当作有效任务。

## 11. Traceback 分析
若直接 `int(input(...))` 且用户输入文字，会得到 `ValueError`；先记录输入和规则。

## 12. 错误案例
把用户输入直接拼进文件路径、Shell 命令或 Agent 工具调用，会造成注入和越权风险。

## 13. 改进方案
检查空白、长度和格式；将解析、验证与业务处理分开。

## 14. 工程实践
输出应说明发生了什么和下一步；错误提示不泄露内部细节。

## 15. 性能优化
交互程序主要等待用户；先保证反馈清晰，而非优化微秒级字符串操作。

## 16. 安全问题
不信任任何外部输入；拒绝危险字符或不允许的字段，并记录最少必要日志。

## 17. 小项目
输入任务标题，拒绝空标题，成功时把任务追加到内存列表并显示数量。

## 18. 单元测试
将解析与验证写成函数，测试空字符串、正常标题和超长文本。

## 19. 自测题
1. `input()` 返回什么类型？ 2. 为什么验证先于转换？ 3. 空标题如何处理？ 4. 输出为何也是接口？ 5. 不信任输入是什么意思？
