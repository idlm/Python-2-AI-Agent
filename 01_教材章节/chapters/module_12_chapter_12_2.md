# 第 12.2 章：能恢复不等于可安全重放——持久化、幂等与审批恢复

**适用版本：** Python 3.11+  
**前置章节：** 第 12.1 章的图编排与框架边界。  
**本章边界：** 设计可测试的恢复合同；不创建真实数据库、网络、账户或副作用工具。

## 1. 本章目标

本章解释为什么长运行 Agent 需要状态保存，也说明恢复会带来重放、身份、隐私与数据保留风险。目标是先写合同，再选 checkpoint 或数据库。

## 2. 什么是 checkpoint

checkpoint 是任务在某一受控位置的状态快照。图运行时可用它恢复线程范围上下文、人工中断与故障后流程；长期 store 则保存跨线程数据。[1]

## 3. 快照不等于事件日志

快照描述“现在是什么”；事件描述“如何到达这里”。两者用途不同：快照便于恢复，最小事件便于解释、审计和评测。不要把完整事件正文塞入快照。

## 4. 任务身份先于保存

恢复需要稳定任务或线程 ID。ID 应有长度、字符、租户范围、不可预测性或冲突策略；不要直接使用邮件地址、自然语言目标、密钥或未经验证的请求头。

## 5. 状态字段闭集

保存前列出允许字段：状态、版本、计数器、停止原因、受控资源标识和最小审批引用。拒绝未知字段，避免提示、工具正文或调试对象随版本漂入存储。

## 6. 状态版本不可省略

结构会改变。状态必须有版本；读取器对旧版本做明确迁移、受控拒绝或人工恢复。静默猜测字段含义会使恢复比故障更危险。

## 7. 可重放与可恢复的差异

可恢复是读取快照后继续；可重放是重复执行某段步骤仍得到可接受结果。保存状态并不会使邮件、转账、删除或外部 API 自动可重放。

## 8. 中断恢复会重跑节点

LangGraph 文档说明，恢复时中断所在节点从开头重跑。[2] 因此节点中断前必须避免不可逆动作，或使用经验证的幂等协议。

## 9. 幂等是什么

对同一受控操作标识重复执行，其目标状态与执行一次一致。它依赖业务语义、外部服务支持和记录设计；不能只靠重试次数或 HTTP 方法名假定。

## 10. 幂等键不是任务 ID

任务 ID 标识工作流；幂等键标识某个副作用请求。一个任务可能含多个行动，各自需要不同键、资源范围和结果查询语义。

## 11. 写前与写后问题

若先写“已完成”再调用工具，崩溃会伪装成功；若先调用再写，崩溃可能重复调用。必须定义准备、已提交、未知结果和人工处置等状态，而非二元猜测。

## 12. 审批恢复值也是不可信输入

`Command(resume=...)` 或任何恢复 payload 只是一段外部数据。应用必须验证批准者、决定枚举、目标资源、过期时间、关联审批 ID 和当前状态。

## 13. 批准不是永久能力

批准应限定到特定动作、资源、版本、时间和一次执行语义。不能把“用户曾批准过”转化为以后任意模型候选都可执行的通行证。

## 14. 审批与参数编辑

若允许审批人修改参数，修改后的值必须重新通过工具 Schema、资源范围、预算和风险检查；不能以“人工改过”跳过验证。

## 15. 最小持久化原则

只保存恢复所需的最小字段。目标正文、对话、提示、工具返回、密钥和个人数据应有独立评估、用途、访问、保留与删除合同，而非默认塞入 checkpoint。

## 16. 保留与删除

持久化系统必须定义何时过期、谁可删除、删除是否覆盖副本、如何证明删除、法律保留例外及故障恢复边界。框架 API 不替代这些治理决定。

## 17. 多租户隔离

恢复查询必须同时验证主体、租户和任务身份。只按 `thread_id` 读状态会让猜中 ID 的人跨越边界；访问控制应在存储与应用入口均有证据。

## 18. 恢复前再验证

恢复时检查状态版本、租户、预算、审批有效性、工具版本、资源存在性和当前策略。旧 checkpoint 不能绕过今天已收紧的安全规则。

## 19. 失败要可处置

不能迁移、找不到状态、版本过旧、审批过期、结果未知或预算耗尽，应产生稳定类别和人工处置入口。不要自动删状态或盲目从头重跑。

## 20. 离线评测如何覆盖恢复

用固定夹具模拟：正常暂停/恢复、拒绝、过期、错任务 ID、旧版本、重复恢复、未知结果。测试应断言工具未被调用，而不只断言最终状态。

## 21. 快速测试（5 题）

1. checkpoint 与事件日志有何差别？2. 为何任务 ID 不等于幂等键？3. 中断恢复为何可能重复副作用？4. 审批恢复值为何不可信？5. 恢复前应检查哪些边界？

## 22. 代码阅读（2 题）

1. 阅读模块 11 的 `stop_reason`，设计它进入持久状态时的版本字段。2. 阅读框架中断说明，指出中断前哪类代码不可放入节点。

## 23. Debug（2 题）

1. 模拟状态版本未知，写出公开错误和人工恢复步骤。2. 模拟批准后资源已删除，说明为何不能继续执行。

## 24. 编程练习（3 题）

1. 定义冻结的 `CheckpointView` 数据类和严格 `from_dict()`。2. 为同一副作用请求实现纯内存幂等登记替身。3. 为恢复 payload 添加审批 ID、决定枚举和过期检查测试。

## 25. 逆向设计与课后项目

**逆向设计：** 某系统保存完整提示和工具返回，用邮箱作 thread ID，审批没有资源范围，中断前已发出请求，崩溃后直接重放。倒推至少十项数据、身份、版本、幂等和人工处置缺失。

**课后项目：** 为模块 11 Agent 制定持久化合同：状态 Schema、版本、最小字段、状态迁移、任务/租户校验、审批恢复 Schema、幂等键策略、保留/删除原则、静态夹具和失败 Runbook。禁止真实数据库和副作用调用。
