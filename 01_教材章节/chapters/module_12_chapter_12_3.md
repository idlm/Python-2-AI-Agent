# 第 12.3 章：工具节点不是能力开关——最小权限、审批与重放防护

**适用版本：** Python 3.11+  
**前置章节：** 第 12.1–12.2 章的图编排、持久化、恢复和幂等合同。  
**本章边界：** 只设计和测试工具包装器；不接入 shell、文件、网络、SQL、MCP、账户、支付或真实模型。

## 1. 本章目标

本章将框架中的“tool node”还原为应用中的受控边界。你将为工具设计名称、Schema、权限、审批、幂等、超时、事件和评测，而不是把 Python 函数直接暴露给模型。

## 2. 工具节点解决什么

工具节点可把结构化工具调用组织进图的状态与路径。它有助于编排，却不自动决定某工具是否存在、谁能用、能访问什么或如何处理失败。[1]

## 3. 工具目录是合同

应用应维护固定工具目录：稳定工具名、版本、输入 Schema、输出类别、资源范围、风险等级和审批策略。模型或框架只能引用目录内条目。

## 4. 不要注册任意 callable

自动扫描函数、动态导入模块或接受用户提供工具名，会把文本变成权限。应使用显式注册表、冻结配置和默认拒绝，与模块 4 和 11 的允许列表原则一致。

## 5. 输入 Schema 不只检查类型

工具参数还需检查字段闭集、长度、枚举、资源归属、路径/URL/查询边界、数量和业务不变量。Pydantic、JSON Schema 或框架类型注解不能替代领域验证。

## 6. 输出也需要 Schema

工具返回同样是不可信环境数据。应用应将其转成有限结果类别和最小公开字段；不要把 HTML、原始 API JSON、堆栈或秘密直接放回模型上下文。

## 7. 最小权限从资源范围开始

工具权限应具体到只读/写入、单一集合、允许域名、账户角色、区域和时间窗口。`admin` 或“可访问全部资料”不是可审查的最小权限设计。

## 8. 工具身份与用户身份分离

执行工具的服务身份、请求发起用户、审批人和模型均不是同一主体。每层应有独立认证、授权和可审计关联，不要把 thread ID 当身份凭证。

## 9. 审批前的最小摘要

审批界面应展示经验证的动作类别、资源范围、影响、幂等键、过期时间和取消方式。它不应默认展示密钥、完整提示、隐私正文或模型推理。

## 10. 批准后必须再验证

批准和执行之间可能改变政策、资源、预算、参数或身份。执行器应在真正调用前重新检查全部合同，而不是相信旧的批准记录。

## 11. 参数编辑后的再审批

若审批人或系统修改了地址、金额、范围或内容，原批准不再覆盖新请求。修改后重新验证，必要时生成新的审批 ID 和新的人类决定。

## 12. 幂等与工具结果查询

高风险工具应使用幂等键和可查询结果状态。若调用后崩溃，系统必须能区分未发送、已成功、已失败和结果未知，不能默认重试。

## 13. 超时不代表撤销

客户端超时只说明没有在预算内得到响应，不证明远端未执行。工具合同应定义超时后的查询、等待、人工处理和禁止重复语义。

## 14. 重试只针对明确类别

仅对有证据可重试且幂等的失败进行有限重试。认证失败、Schema 失败、审批拒绝、策略拒绝和未知结果不应自动重放。

## 15. 工具输出不能授权下一步

网页、数据库、MCP 或模型返回的文字都可能含提示注入。工具输出只作为数据，不能改变工具目录、审批、预算或系统策略。[2]

## 16. 图中正确的工具路径

建议路径为：候选→Schema 验证→权限检查→预算检查→审批（如需）→执行前再验证→包装工具→结果分类→最小事件→受控下一步。每一箭头可独立测试。

## 17. 中断前放什么

中断前可放纯验证、受控摘要构造和审批记录；不要放发送、扣费、写库、删除、不可撤销 token 消耗或无幂等 API 调用。恢复会使节点从开头运行。[3]

## 18. 评测工具控制

离线夹具应覆盖未知工具、额外字段、跨租户资源、预算耗尽、拒绝审批、过期批准、修改参数、超时和注入结果。重点断言“没有调用工具”。

## 19. 事件与日志最小化

事件记录工具类别、结果类别、步骤、状态和非秘密关联 ID；日志按需记录调试元数据。原始参数、结果、提示和响应须有独立、经过审查的数据治理设计。

## 20. 框架升级不应改写合同

升级图框架、模型 SDK 或工具集成包前，先跑 Schema、审批、预算、幂等、隐私和离线回放测试。若测试通过却权限语义改变，升级仍应阻断。

## 21. 快速测试（5 题）

1. 工具节点和工具授权有何不同？2. 为什么输入与输出都要验证？3. 为何批准后需再验证？4. 超时为何不等于撤销？5. 工具结果为何不能新增权限？

## 22. 代码阅读（2 题）

1. 把模块 11 的 `LOOKUP_PUBLIC_FACT` 写成工具目录条目。2. 为一个假“写入”工具标出审批前、审批后、执行前的验证位置。

## 23. Debug（2 题）

1. 让审批人把只读资源改成写入资源，说明如何拒绝旧批准。2. 模拟工具超时后收到成功回执，说明为何不能盲目重试。

## 24. 编程练习（3 题）

1. 定义 `ToolDescriptor` 冻结数据类和工具目录字段闭集。2. 写纯函数 `validate_candidate()`，拒绝未知工具与额外参数。3. 写无副作用审批重新验证测试，断言编辑参数后旧审批无效。

## 25. 逆向设计与课后项目

**逆向设计：** 一个图框架自动从函数文档生成工具、模型可选择任何工具、审批显示完整提示、超时自动重试、恢复后直接执行。倒推至少十项授权、数据、幂等和评测控制缺失。

**课后项目：** 为一个假“发送通知”工具提交工具目录、输入/输出 Schema、最小权限矩阵、审批摘要、幂等/超时语义、执行前再验证、最小事件、十条离线负向夹具和发布门禁。禁止真正发送通知。
