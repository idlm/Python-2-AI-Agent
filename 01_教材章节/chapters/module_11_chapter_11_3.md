# 第 11.3 章：模型只能提议，程序才可授权——行动候选、审批与停止条件

**适用版本：** Python 3.11+  
**项目连接：** `projects/11-bounded-agent-core/`（v0.1.0）  
**前置章节：** 第 11.1–11.2 章的状态、纯工具、事件与静态评测。

## 1. 本章目标

本章说明 Agent 中最重要的分工：模型或规划器只能提出行动候选；应用代码验证动作、参数、状态、预算与审批后才允许执行。

## 2. 候选不是执行

`lookup_public_fact` 是枚举动作，不是模型返回的一段自由文字。模型写出“删除文件”不会创建对应能力，因为程序没有该动作合同。

## 3. 为什么文本不能直接变 callable

把模型输出导入、`eval`、映射到任意函数或交给 shell，会把不可信文本变成权限。提示注入特别容易借此影响下游工具。[1]

## 4. 固定动作允许列表

当前项目仅有查询、完成和审批请求。允许列表应小、可测试、可说明；增加动作前先写输入 Schema、失败语义、权限、超时、审计与测试。

## 5. 参数验证早于工具调用

纯工具参数必须非空且最多 120 字符。验证失败时工具不运行。不要为“方便”自动补全路径、URL、SQL、账户或默认命令。

## 6. 状态验证早于动作

只有 `running` 能执行步骤。`completed`、`stopped` 和 `waiting_for_approval` 不能偷偷调用工具。状态守卫把“下一步是否可能”放在模型外。

## 7. 预算验证早于循环

当步骤达到上限，任务停止并记录 `step_budget_exhausted`。预算是停止控制，不是质量、事实或安全保证。

## 8. 审批请求不是批准

`request_approval` 仅暂停。实际批准来自应用的显式 `approve()` 调用；拒绝停止任务。模型生成的“approved”不改变状态。

## 9. 审批摘要应最小化

现实系统应给人展示受控操作类别、资源范围、影响、理由和取消方法，而不是原始提示或秘密。审批人、时间和决定也需要独立审计设计。

## 10. 工具结果是环境反馈

工具结果可帮助 Agent 选择下一步，但不自动证明事实、权限或最终决策正确。检索、来源、人工复核和领域规则仍在模型外。

## 11. 纯工具是教学起点

纯工具不改变现实世界，使状态和评测可重复。它不是生产副作用工具的等价替身；写文件、转账、发邮件和修改账户必须拥有更严格的权限与审批。

## 12. 一步一验证

安全循环是：读取状态→验证候选→检查预算→调用允许工具→验证结果类别→写最小事件→检查停止。不要先执行再试图补救。

## 13. 失败类别要稳定

非法状态、非法参数、未知动作、预算耗尽和审批拒绝必须可区分。把全部错误折叠为“agent failed”会使测试、告警和人工处置失去信息。

## 14. 停止原因不是异常堆栈

`approval_denied` 和 `step_budget_exhausted` 是受控业务结果。异常可在内部调试，但对调用者应给稳定类别而非泄露实现细节。

## 15. 输入不可信的边界

用户、文档、网页、工具返回和模型输出都应视为数据。开发者/系统策略、动作允许列表、参数验证和审批流程是应用控制，不可由这些数据覆盖。[1]

## 16. 小系统也需要评测

静态夹具回放完成、拒绝、预算和注入案例。测试的目标不是“让 Agent 看起来聪明”，而是发现合同退化。

## 17. 评测不能授权

评测报告通过，不会批准新的工具、提高预算、打开网络或允许模型自动行动。配置变更必须经过独立代码审查和风险评估。

## 18. 什么时候需要人工介入

敏感数据、不可逆行动、异常结果、预算耗尽、冲突信息和低置信候选都可成为暂停条件。规则应明确、可审查、可测试。

## 19. 框架仍是实现选择

SDK 可运行循环、管理 state 或 traces，[2] 但不能决定你的允许列表、审批阈值、数据保留或责任边界。先理解本章合同，再比较框架。

## 20. Agent 不等于自主化

可控系统可以在任务范围内动态选择下一步，同时拒绝未知动作、限制预算并在审批点停止。自治程度是产品与风险决策，不是技术炫耀。

## 21. 快速测试（5 题）

1. 候选和执行有何差别？2. 为什么参数验证必须早于工具？3. 预算耗尽代表什么？4. 为什么审批文本无效？5. 纯工具为何不能直接推广到转账工具？

## 22. 代码阅读（2 题）

1. 阅读 `step()`，按顺序列出状态、预算、审批、完成、工具和参数检查。2. 阅读夹具解析器，解释为何额外字段被拒绝。

## 23. Debug（2 题）

1. 让已完成任务请求查询，确认状态守卫失败。2. 让夹具动作序列为空，确认不是默默通过。

## 24. 编程练习（3 题）

1. 增加工具调用独立预算。2. 增加审批操作 ID 并测试错配拒绝。3. 增加固定结果类别 Schema 并拒绝未知类别。

## 25. 逆向设计与课后项目

**逆向设计：** 一个系统把模型 JSON 直接映射到 shell，审批文本即执行，预算耗尽后重置计数继续，评测通过即开放网络。倒推至少八项控制缺失。

**课后项目：** 完成一个仅有纯工具的受限 Agent：候选枚举、参数 Schema、状态/预算守卫、审批暂停、最小事件、静态夹具、无正文报告、CLI和质量门。禁止真实副作用。
