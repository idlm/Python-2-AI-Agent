# 第 3.3 章：CSV、JSON 与 YAML——让数据可交换、可验证

## 1. 本章目标
理解表格、对象和配置三类结构化数据的基本适用边界。

## 2. 为什么学习
任务、配置、日志和知识库元数据都需要可持久化和可交换的结构。

## 3. Agent 中的作用
工具参数、状态快照、评测集和 RAG 元数据需要稳定 Schema 与可追溯格式。

## 4. 前置知识
完成第 3.1–3.2 章。

## 5. 概念解释
CSV 表示行列数据；JSON 表示对象与数组；YAML 常用于人可读配置。格式不是业务规则本身，仍需验证。

## 6. 生活化比喻
CSV 像表格，JSON 像嵌套任务卡，YAML 像配置清单。

## 7. 原理分析
选择格式取决于数据形状、读写者、嵌套程度和验证需要；不同格式之间可转换，但字段语义不能丢失。

## 8. 最小示例
```python
import json
record = {"title": "学习 JSON", "done": False}
text = json.dumps(record, ensure_ascii=False)
print(json.loads(text)["title"])
```

## 9. 逐行解释
字典保存结构；`dumps` 序列化为文本；`loads` 解析回对象。

## 10. 常见错误
不要手拼 JSON；不要假设所有 CSV 字段都是正确类型；不要把 YAML 当作不受限执行脚本。

## 11. Traceback 分析
无效 JSON 会产生 `JSONDecodeError`；应报告文件、行列和安全上下文，不打印敏感全部内容。

## 12. 错误案例
配置字段拼写错误后被默默忽略，归档工具使用错误目标目录。

## 13. 改进方案
定义必填字段、类型、默认值和拒绝未知关键配置的策略；加载后立即验证。

## 14. 工程实践
数据文件使用 UTF-8；记录 Schema 版本；迁移旧格式时保留原始备份。

## 15. 性能优化
大 CSV 流式读取；避免一次加载超大 JSON；根据访问模式选择格式。

## 16. 安全问题
不加载不可信 YAML 的任意对象；限制文件大小、嵌套深度与允许字段；敏感配置不入库。

## 17. 小项目
将任务列表保存为 JSON，再重新读取并验证标题与状态字段。

## 18. 单元测试
测试序列化往返、缺失字段、无效 JSON 和 UTF-8 中文文本。

## 19. 自测题
