# 第 4.1 章：类与对象——把相关状态和行为组织在一起

## 1. 本章目标
理解类定义对象的结构与行为，能创建最小任务对象。

## 2. 为什么学习
当数据和操作不断增长，散落的字典与函数难以维护。

## 3. Agent 中的作用
工具、消息、状态和插件可以用对象表达边界、状态与行为。

## 4. 前置知识
完成模块 1 的字典与模块 2 的函数。

## 5. 概念解释
类是创建对象的蓝图；对象保存自己的属性并提供方法；`self` 表示当前对象。

## 6. 生活化比喻
类像任务卡模板，对象像根据模板创建的具体任务卡。

## 7. 原理分析
对象将相关数据和函数放在一起，减少调用者直接修改内部状态的机会。

## 8. 最小示例
```python
class Task:
    def __init__(self, title: str) -> None:
        self.title = title
        self.done = False
    def complete(self) -> None:
        self.done = True
```

## 9. 逐行解释
类名描述概念；初始化方法设置初始状态；方法通过 `self` 修改当前任务。

## 10. 常见错误
忘记 `self`；把类当作对象直接使用；让外部代码随意修改所有属性。

## 11. Traceback 分析
调用不存在方法会产生 `AttributeError`，说明对象接口与调用假设不一致。

## 12. 错误案例
任务字典在多处使用不同键名，完成功能必须知道所有历史写法。

## 13. 改进方案
将创建和完成规则放进 Task 对象，暴露小而清晰的公开方法。

## 14. 工程实践
对象应保持不变量，例如 `done` 总是布尔值；方法负责守护规则。

## 15. 性能优化
不要为每个小值机械建类；在状态、行为和边界共同存在时再使用对象。

## 16. 安全问题
对象方法仍须验证外部输入；封装不是权限控制替代品。

## 17. 小项目
把任务管理器的单条任务重构为 `Task` 类，提供 `complete()` 方法。

## 18. 单元测试
测试新任务未完成，调用 `complete()` 后完成状态为真。
