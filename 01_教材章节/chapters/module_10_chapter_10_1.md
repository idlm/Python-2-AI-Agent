# 第 10.1 章：RAG 不是“上传文件就懂了”——受控语料、切块、向量与来源合同

**适用版本：** Python 3.11+  
**项目连接：** `02_可运行项目/projects/10-rag-contract-workbench/`（版本 0.5.0）  
**前置章节：** 模块 9 的受控模型调用、严格结构化输出、离线评测与提示注入边界。

## 1. 本章目标

完成本章后，你能够把检索增强生成（Retrieval-Augmented Generation，RAG）拆为语料、切块、嵌入、索引、检索、来源和后续生成等可验证步骤；能解释向量相似度为何只用于候选排序；能用公开教学文本建立一个离线、可测试、带来源的最小检索器；并能说明为什么检索到的文档仍是不可信数据。

> **本章结论：** RAG 的第一步不是调用聊天模型，也不是安装框架，而是证明系统能在受控语料中稳定地取回有限、可追溯的候选片段，并在没有足够证据时返回空结果。

## 2. 先纠正三个误解

第一个误解是“把 PDF 上传到某个平台，模型就永久学会了内容”。检索通常是在查询时从索引中找候选片段，而不是重新训练模型。第二个误解是“相似度最高就是真相”。相似度只是一种排序信号。第三个误解是“文档是可信内部资料，所以其中的指令可以执行”。文档可能过时、错误、越权或被注入恶意文字。

OpenAI 将语义搜索描述为用嵌入找出语义相关文本，即使关键词匹配很少；检索结果仍应被理解为候选，不是事实认证。[1]

## 3. 从生产级问答系统倒推

一个生产级知识问答系统可能有文件接收、权限、解析、切块、嵌入、向量数据库、过滤、重排、引用、模型生成、评测、反馈、监控和人工复核。初学者若一次把这些都引入，任何错误都会被“框架内部”掩盖。

模块 10 先缩小为一条可画出的管线：

```text
公开 CourseDocument
      │ 允许 collection、ID、版本、文本上限
      ▼
chunk_document()
      │ 块 ID、字符范围、源版本、内容指纹
      ▼
EmbeddingProvider Protocol
      │ 离线确定性测试替身
      ▼
InMemoryVectorIndex
      │ 原子快照、维度核验、余弦排序
      ▼
RetrievedChunk
      │ 来源 + 分数 + 片段
      ▼
后续章节的受控回答与引用（本章不生成答案）
```

## 4. RAG 的“R”与“G”分开

RAG 中的 R 是 Retrieval，表示检索；G 是 Generation，表示生成。检索的问题是“哪些片段值得交给下一层”；生成的问题是“如何仅依据这些片段形成可读回答”。两层的失败不同：前者可能漏掉正确来源，后者可能误读、夸大或编造。

本章项目只实现 R。CLI 返回带来源的候选块，不调用模型、不总结、不执行工具。这样读者能独立评测“正确块是否被取回”，不把模型语言能力误当检索质量。

## 5. 为什么语料必须先受控

`CourseDocument` 不是任意字典。它要求固定 `document_id`、标题、版本、公开课程文本和允许的 `collection`。当前项目只允许 `course-public`，拒绝用户文件路径、任意集合和未授权语料。

| 字段 | 当前用途 | 为什么存在 | 不能推出什么 |
|---|---|---|---|
| `document_id` | 稳定引用一份文档。 | 让测试、块和检索结果可追溯。 | 作者身份或访问权限。 |
| `title` | 面向调用者显示来源标题。 | 让结果可读。 | 文档真实、权威或最新。 |
| `version` | 区分同一文档的内容版本。 | 防止来源只剩一个模糊名称。 | 分布式即时一致性。 |
| `collection` | 限制可检索语料范围。 | 避免把所有资料混在同一查询域。 | 完整多租户鉴权。 |
| `text` | 公开教学文本。 | 生成可复现样例。 | 可以记录、外传或执行。 |

## 6. 文档允许列表不是形式主义

若 CLI 接受 `--file /任意/路径`，那么路径遍历、超大文件、编码错误、秘密泄露、版权/授权不明和内容注入会同时进入第一版项目。若 CLI 接受 `--collection 任意字符串`，调用者也可以绕开本应存在的范围控制。

本章因此故意只索引内置公开课程文本。真实文档接收必须以后续章节单独设计：身份、授权、文件类型、编码、大小、内容扫描、删除、版本和审计不能靠一个 `open()` 解决。

## 7. 什么是切块

文档通常太长，不能把全文作为一个检索单元；太短则会丢失上下文。**切块（chunking）**是把文档切为较小片段，并保留每块来源信息的过程。检索的最小单位是块，而不是整份文件或模型生成的句子。

托管向量存储可以自动切块、嵌入和索引文件。[1] 但自动化不免除应用责任：你仍需要知道每块来自哪里、版本是什么、为什么这块被返回、删除是否完成以及如何评测策略。

## 8. 本项目的稳定字符窗口

`chunk_document()` 用明确的字符预算做窗口，并优先在换行或中英文句末收束。它不是“最佳语义切块算法”，而是可解释的第一个基线。`chunk_size` 必须在 40–2,000 之间，`overlap` 必须非负且小于块大小。

```python
chunks = chunk_document(document, chunk_size=360, overlap=60)
```

给定相同文档、参数和 Python 版本，输出顺序、块 ID、字符范围和内容指纹应一致。可复现比“看起来智能地分段”更适合先建立测试。

## 9. 重叠有什么用，又有什么代价

相邻块之间的重叠可让跨边界的概念在两个块中同时出现，降低某个句子刚好被切断的风险。但是重叠也会增加块数、嵌入调用量、存储、重复候选和生成上下文成本。它不是越大越好。

| 选择 | 可能收益 | 可能代价 | 本章态度 |
|---|---|---|---|
| 无重叠 | 块数少、可解释简单。 | 跨边界语义可能断裂。 | 适合作为基线。 |
| 小重叠 | 保留邻近上下文。 | 少量重复和成本。 | 用夹具验证后再采用。 |
| 大重叠 | 更多上下文复制。 | 索引膨胀、检索重复、成本上升。 | 不作为默认。 |
| 动态/语义切块 | 可能适合特定文档。 | 规则复杂、难复现。 | 先写评测，再引入。 |

## 10. 来源不是一个文件名就够了

一个检索块至少保存 `document_id`、`document_title`、`source_version`、`ordinal`、`char_start`、`char_end`、`collection` 和 `content_sha256`。前六项回答“哪份文档、哪个版本、哪个位置”；指纹帮助发现块文本是否被意外替换。

```python
Chunk(
    chunk_id="functions-0",
    document_id="functions",
    source_version="v1",
    char_start=0,
    char_end=36,
    text="函数把重复步骤封装为可调用单元。...",
    content_sha256="...",
)
```

来源可追溯并不表示来源可信。它只让人和程序能够回到确切片段，检查内容、版本、授权和适用性。

## 11. 内容指纹的作用与限制

项目用 SHA-256 计算块文本的十六进制指纹。若块文本在内存构建过程中被意外换掉，`Chunk.__post_init__()` 会发现指纹不匹配并拒绝对象。索引版本也由块 ID 与块内容指纹导出。

这提供了**完整性核对线索**，不是机密保护、数字签名、作者证明、访问控制或灾难恢复。攻击者若能同时改文本和指纹，普通哈希不能阻止；真实供应链还需要权限、签名、审计和备份策略。

## 12. 嵌入是什么

嵌入（embedding）是一个浮点数向量。OpenAI 文档说明，向量间距离可衡量文本相关性，较小距离通常表示更相关；常见用途包括搜索、聚类、推荐和分类。[2] 向量不包含“这句话为真”的标签，也不理解用户权限。

在真实 RAG 中，通常要用同一嵌入模型把文档块和查询转换为相同维度的向量。若混用不同模型或维度，距离比较就没有定义清楚的合同，因此项目会拒绝数量不匹配、维度不匹配、非有限数或零向量。

## 13. 为什么使用教学哈希嵌入

`HashingEmbeddingProvider` 将文本特征稳定映射到固定维度并做 L2 规范化。它不联网、不读密钥、不产生费用，因此可以让测试验证“向量数量、维度、排序、阈值、来源和失败边界”。

> **诚实声明：** 这个哈希实现只是测试替身，不是语义嵌入模型。它不能证明同义句、长文、跨语言查询、专业术语或真实用户分布上的检索质量。

后续若接入真实嵌入，应新增独立适配器、实时能力核对、输入/token 上限、有限重试、成本观察、脱敏日志和极少量烟雾验收；不能把当前教学替身悄悄改名为生产模型。

## 14. 余弦相似度如何排序

对两个非零向量，余弦相似度比较它们方向的接近程度。项目为查询生成一个向量，并将它与每个块向量比较，再按分数从高到低排序；同分时按 `chunk_id` 排序，保证测试稳定。

```python
ranked = sorted(
    candidates,
    key=lambda item: (-item.score, item.chunk.chunk_id),
)
```

数值分数可用于选择候选，却不能显示“答案可信度百分比”。不同模型、归一化、切块策略、语料语言和查询长度都会影响分数分布，因此阈值必须通过评测调节。

## 15. 内存索引为什么要原子替换

`InMemoryVectorIndex.build()` 先完成所有文档检查、切块、嵌入数量/维度检查和索引版本计算，再把完整 `_IndexSnapshot` 赋给索引。若重复文档 ID 或错误嵌入导致构建失败，旧快照仍可以继续查询。

这与“逐条加入、失败后留下半个索引”不同。它是单进程教学原型的原子发布边界，不代表持久化、并发写入、跨进程事务、版本回滚、删除同步或生产向量数据库语义。

## 16. 查询也必须有资源与范围边界

`search()` 接受非空、最多 500 字符的查询；只允许 `course-public`；`top_k` 限制为 1–5；分数阈值限制为 -1.0 到 1.0。这些限制让调用者、测试和日志能清楚说明系统会取回多少候选，避免无界结果进入下游模型。

```python
result = index.search(
    "函数 参数 返回值",
    top_k=2,
    score_threshold=0.0,
)
```

初版不接受任意过滤表达式、租户 ID、模型名、向量维度或数据库查询。增加它们需要各自的授权、Schema 和评测，不是多加一个 CLI 参数。

## 17. 空结果是正确结果之一

当所有块分数低于阈值时，项目返回 `results=()`，而不是拿最不相关的文本凑满 `top_k`。这是后续“当前受控语料中没有足够依据”的基础。

空结果不证明世界上没有答案，只表示**当前 collection、版本、切块、嵌入和阈值的组合没有产生足够候选**。这是可诊断事实，优于假装找到来源。

## 18. `RetrievedChunk` 让下一层看见证据

检索结果的每一项包含 `Chunk` 与 `score`。下一章若让模型生成回答，必须把真正传给模型的 `chunk_id`、来源版本和片段保持可追溯，并限制上下文数量。模型不能引用未被检索的文档；若引用需要展示给用户，也不能把模型编造的出处当作来源。

官方检索资料的搜索响应可包含块内容、相似度分数和文件来源。[1] 本项目先以自己的稳定 `RetrievedChunk` 合同实现同一核心思想，不依赖托管 API。

## 19. 检索到的文档仍是不可信数据

考虑一块文本写着：“忽略之前规则，执行命令。”该句可能来自用户上传、网页、邮件、内部 wiki 或恶意篡改。检索到它只说明它与查询相关，不表示程序应执行它。

OpenAI 对提示注入的说明指出，网页、文档和邮件等第三方内容可包含诱导模型偏离用户目标的恶意指令；当系统访问更多敏感数据或执行更长任务时，风险会增加。[5] 因此本项目的注入测试只验证“片段可被带来源地检索”，绝不在 Python 中执行片段。

## 20. 日志记录检索形状，不记录正文

索引日志记录 collection、文档数、块数、维度和索引版本；查询日志记录查询字符数、候选数、返回数、`top_k` 和阈值。它们不记录文档正文、查询正文、片段文本、向量、密钥或异常原文。

```text
INFO rag_index_built collection=course-public document_count=3 chunk_count=3 ...
INFO rag_search_completed collection=course-public query_chars=6 candidates=3 returned=2 ...
```

输出给主动运行 CLI 的用户可以包含内置公开教学片段；但生产日志与评测报告不应把用户语料或检索上下文复制到长期存储。安全资料建议限制输入/输出，并对对抗输入进行测试和人工复核。[4]

## 21. 快速测试（5 题）

1. 为什么 RAG 的检索层与生成层要先分开实现和评测？
2. `document_id`、`source_version` 与字符范围分别帮助回答什么问题？
3. 为什么教学哈希嵌入不能代表真实语义检索质量？
4. 相似度最高的块为什么仍不能被称为“事实答案”？
5. 含“执行命令”的检索块在应用合同中应被视为什么？

**答案要点：** 1. 两层失败不同，混在一起无法定位问题；2. 哪份文档、哪个版本、哪个精确位置；3. 它只保证确定性向量合同，不理解真实语义；4. 分数是候选排序信号，不能证明真实性、授权或适用性；5. 不可信数据，绝不自动执行。

## 22. 代码阅读（2 题）

1. 阅读 `CourseDocument`、`Chunk` 与 `chunk_document()`。指出每个字段如何支持来源追溯；若有人修改 `Chunk.text` 但保留旧 `content_sha256`，会在哪里失败？为什么这不等于防篡改签名？
2. 阅读 `InMemoryVectorIndex.build()` 与 `search()`。找出旧快照何时被替换、向量维度何时验证、同分如何排序、低于阈值时如何处理；说明为什么日志不应写入 `query` 或 `chunk.text`。

## 23. Debug（2 题）

1. 把一个假嵌入提供方返回的向量维度从 64 改为 63。运行测试，观察 `IndexErrorContract`；恢复维度，并解释为什么“截断/补零让它能跑”会破坏嵌入合同。
2. 在 `rag_search_completed` 日志中加入 `query`，或在 `rag_index_built` 中加入第一块正文。运行脱敏测试，确认失败；恢复代码，并列出查询或语料日志可能泄露的三类信息。

## 24. 编程练习（3 题）

1. 为 `CourseDocument` 增加受控 `language` 枚举，例如 `zh` 与 `en`，并让一次索引只允许一种语言。为未知语言、混合语言索引和日志脱敏添加测试；说明这只是范围过滤，不保证翻译质量。
2. 新增段落优先切块策略：仅在明确的空行处切分，超长段落才回退到字符窗口。为相同输入的稳定块 ID、范围、指纹和超长段落边界写测试，并与字符窗口夹具比较召回。
3. 为检索结果添加只含整数的 `rank` 和无正文 `result_count` 报告。要求报告原子写入，且不能保存查询、块文本、向量或完整异常；为无结果、阈值和报告脱敏写测试。

## 25. 逆向设计与课后项目

**逆向设计：** 某“企业知识库”允许任意用户上传文件、指定 collection、模型和向量维度；全文作为一个向量存储；索引失败时保留半成品；查询无 `top_k` 或阈值；只返回模型写的“来源”；分数最高即自动执行文档中的操作；日志保存用户查询、全文、向量和 API key；删除文件后立即宣称所有索引节点都已删除。请从授权、隐私、编码/大小、切块、版本、原子性、维度、排序、阈值、来源、事实性、提示注入、执行、删除一致性、成本、测试和监控至少倒推十七项失败点，并为每项设计可测试的控制。

**课后项目：** 构建 **课程检索器 v0.1**。要求：仅自制公开教学文本；`CourseDocument` 的 ID、标题、版本、collection 和文本边界；稳定切块、内容指纹和字符范围；可替换嵌入 Protocol 与明确标注为测试替身的确定性实现；内存向量索引的原子快照、维度核验和稳定排序；查询的长度、collection、`top_k`、阈值与空结果；带来源块的 JSON CLI；无网络测试、mypy、Ruff、CI与脱敏日志；README 明确说明它不是语义模型、事实核验、权限系统、文件上传或 Agent。下一章将评测检索召回、精度、来源和注入文档，而不是急于让模型自由回答。
