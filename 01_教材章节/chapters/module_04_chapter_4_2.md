# 第 4.2 章：继承与组合——复用行为而不制造脆弱层级

## 1. 本章目标
理解继承与组合的差异，并优先用组合构建可替换插件。

## 2. 为什么学习
复用代码不等于建立长继承链；错误层级会让修改影响不可预测。

## 3. Agent 中的作用
模型、工具、记忆和检索器通常通过组合协作，而非被强行塞进单一基类。

## 4. 前置知识
完成第 4.1 章。

## 5. 概念解释
继承表达“是一种”；组合表达“拥有或使用一种能力”。

## 6. 生活化比喻
电动车是一种车可继承车辆规则；车辆拥有电池是组合关系。

## 7. 原理分析
继承共享父类接口与实现；组合通过持有对象并委托调用实现可替换行为。

## 8. 最小示例
```python
class Formatter:
    def format(self, text: str) -> str:
        return text
class Report:
    def __init__(self, formatter: Formatter) -> None:
        self.formatter = formatter
```

## 9. 逐行解释
Report 不继承 Formatter，而是接收一个 Formatter 对象；调用者可替换实现。

## 10. 常见错误
不要仅为复用一段代码建立继承；不要让子类违背父类承诺。

## 11. Traceback 分析
错误方法解析或缺失方法可能产生 `AttributeError`；检查对象实际类型与公开接口。

## 12. 错误案例
把所有插件继承巨大基类，任何新插件都必须实现无关方法。

## 13. 改进方案
定义小协议，使用组合注入所需依赖；继承仅用于稳定“是一种”关系。

## 14. 工程实践
依赖面向接口；构造函数接收依赖；测试时替换假对象。

## 15. 性能优化
组合层数不是主要瓶颈；优先保持可测试与可替换。

## 16. 安全问题
插件必须具备权限边界；组合不应让不可信插件获得全部系统能力。

## 17. 小项目
为插件系统设计 `Formatter` 协议和两个可替换格式化实现。

## 18. 单元测试
测试替换格式化对象后 Report 输出变化，且无需修改 Report 本身。

## 19. 自测题
1. 是一种与拥有一种区别？ 2. 为何偏好组合？ 3. 继承何时适合？ 4. 接口有什么用？ 5. 插件权限如何限制？
