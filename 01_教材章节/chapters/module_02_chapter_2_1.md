# 第 2.1 章：函数——把步骤命名为可复用能力

## 1. 本章目标
理解函数将重复步骤封装为有名称、输入和输出的单元。

## 2. 为什么学习
任务分析、文本清洗和 Agent 工具都需要把大问题拆小。

## 3. Agent 中的作用
工具本质上是有明确输入输出与失败边界的函数或服务接口。

## 4. 前置知识
完成模块 1。

## 5. 概念解释
函数用 `def` 定义，调用时执行；函数名应表达业务责任。

## 6. 生活化比喻
函数像写好步骤的食谱：给定材料，按规则得到结果。

## 7. 原理分析
将重复逻辑放进函数，调用者只需知道契约而不必复制内部细节。

## 8. 最小示例
```python
def normalize_title(title: str) -> str:
    return title.strip()
print(normalize_title("  学习函数  "))
```

## 9. 逐行解释
`def` 创建函数；参数接收输入；`return` 把结果交还调用者。

## 10. 常见错误
定义函数不等于调用函数；不要让一个函数承担无关责任。

## 11. Traceback 分析
参数缺失会产生 `TypeError`，提示调用违反函数契约。

## 12. 错误案例
复制三段相同清洗逻辑，修改一处却漏掉另外两处。

## 13. 改进方案
提取一个函数，并为正常、空白和异常输入编写测试。

## 14. 工程实践
函数名用动词，输入输出明确，副作用最小。

## 15. 性能优化
先消除重复和明确边界，再测量真正瓶颈。

## 16. 安全问题
函数不得信任外部输入；验证应靠近边界。

## 17. 小项目
为文本分析工具设计 `count_words` 与 `normalize_text` 两个函数。

## 18. 单元测试
测试相同输入得到相同结果，边界输入有明确行为。

## 19. 自测题
1. 函数解决什么问题？ 2. 定义与调用区别？ 3. 什么是契约？ 4. 为什么少副作用？ 5. 如何命名？

## 20. 代码阅读题
