# 第 10.4 章：检索命中不等于回答可信——回答支持度评测、人工复核与报告隐私

**适用版本：** Python 3.11+  
**项目连接：** `02_可运行项目/projects/10-rag-contract-workbench/`（v0.5.0）  
**前置章节：** 第 9.3 章的离线模型评测；第 10.1–10.3 章的检索评测、来源约束回答与严格 JSON。

## 1. 本章目标

本章把评测从“是否取回正确块”推进到“候选回答是否遵守状态、引用和复核合同”。你将能区分检索评测与回答评测；设计公开静态夹具；检查回答状态、引用子集、术语覆盖和人工复核信号；生成不含问题、来源、回答或术语字面量的报告；并正确解释一次真实烟雾调用的范围。

> **核心原则：** 回答评测可以发现合同破坏和已知案例中的支持不足，但不能自动认证事实、来源权威、权限、适用性或安全。

## 2. 为什么检索评测之后还要测回答

检索评测关注目标块是否在 `top_k`、噪声比例、来源字段和空结果。即使这些都通过，模型仍可能忽略关键限制、错误概括、漏掉引用、选择不相关块、把“不足”说成“已回答”，或者错误关闭人工复核。

| 层 | 问题 | 典型门 |
|---|---|---|
| 切块/索引 | 文档是否稳定可追溯？ | ID、范围、版本、维度。 |
| 检索 | 正确来源是否被返回？ | 召回、精度、阈值、空结果。 |
| 回答合同 | 输出是否符合来源约束？ | 状态、JSON、引用白名单、长度。 |
| 回答支持度 | 已知案例是否保留必要概念和复核？ | 术语计数、来源子集、复核标记。 |
| 人工判断 | 结论是否正确、完整、适用和可行动？ | 专业审查、升级流程、责任边界。 |

## 3. 静态夹具是可重复起点

项目的 `tests/fixtures/answer_evaluation.json` 是课程自制公开夹具。每个案例只定义案例 ID、非内容标签、期望状态、允许引用 ID、是否要求人工复核和最低术语集合。它不包含真实用户问题、私有语料或供应商响应。

静态夹具不是现实分布的完整样本，也不是基准排行榜。它的价值是每次改代码、提示、模型适配器或索引参数时，都能用同一合同发现退化。

## 4. 回答状态必须先匹配

评测首先比较实际 `AnswerStatus` 和案例 `expected_status`。例如，语料外案例应是 `not_enough_evidence`；如果候选回答声称 `answered`，即使文字流畅也失败。反过来，有充分证据却一律拒答也需要被发现。

状态评测的前提是产品已经明确定义状态。不能用“置信度高”代替状态，因为置信度来源、含义、校准和展示责任都未定义。

## 5. 引用子集是必要而非充分条件

评测计算实际引用 ID 是否为该案例允许引用集合的子集。未知引用立刻失败；空证据不应带引用；有证据的回答至少应带一个允许引用。这复用了第 10.3 章的模型外白名单原则。

```python
actual_ids = {citation.chunk_id for citation in answer.citations}
citation_subset_valid = actual_ids <= set(case.allowed_citation_ids)
```

子集通过只说明“没有引用本案例之外的块”，不说明块确实支持句子。为了提高可审查性，仍要检查最低术语、保留人工复核，并在高风险领域使用专业审查。

## 6. 最低术语覆盖不是语义理解

课程夹具可要求回答包含少量关键术语，如“参数”和“返回值”。评测只记录命中数量和所需数量，不持久化术语本身。这样可以发现明显遗漏，却不能证明同义表达、因果关系、否定词、数字、范围或推理正确。

> 不要把关键词命中率改名为“事实准确率”。它只是当前夹具中的最小可观察信号。

## 7. 人工复核是可测试字段

`needs_human_review` 不是装饰性布尔值。夹具可要求某些案例必须为真，尤其是来源不可信、信息不足、政策性或可能影响现实决定的回答。评测检查模型候选是否保留了这一信号。

字段为 `True` 不会自动派发工单，也不等同于已经审核。产品还需要定义谁复核、何时复核、可看到哪些最小证据、如何记录决定以及超时怎么办。

## 8. 把评测输入和公开报告分开

夹具与候选回答在受控测试目录和内存中使用；公开报告只写安全摘要。项目的 `AnswerEvaluationResult` 含案例 ID、分类标签、实际状态、预期/实际引用数、引用子集布尔值、术语数量、复核匹配与通过状态。

它不写问题、文档块、候选回答、系统提示、术语字面量、向量、密钥或原始 SDK 响应。这与模块 9 的最小化报告原则一致。

## 9. 原子写入仍然必要

评测报告也是持久化数据。项目先在同一目录创建临时文件，完成 JSON 写入后以 `replace()` 更新目标。若写入过程失败，旧报告保留，调用者不会读到半截 JSON。

原子替换不等于跨机器事务、永久备份或并发协调。它只缩小单文件更新时“文件被截断”的常见失败窗口。

## 10. 回答评测的通过公式要公开

项目将以下条件组合为 `passed`：状态匹配；引用满足状态规则并属于允许集合；人工复核信号匹配；所有最低术语出现。任何一项失败，案例失败。

```python
passed = (
    status_matches
    and citations_match
    and review_matches
    and matched_term_count == len(case.required_terms)
)
```

显式布尔组合比把多种失败压成一个神秘分数更适合初学者排查。真实产品可以增加加权指标，但必须保留每一项的定义、阈值、失败原因和人工复核解释。

## 11. 失败案例：未知引用

如果模型写出 `unknown-0`，`citation_subset_valid` 为假，即使回答包含所有术语也不能通过。这是正确的：不能为了让汇总指标好看而删除未知引用或把它改成最近的块。

静默修复会让系统从“模型发生来源伪造”变成“无从追踪的展示改写”。正确处理是报告失败、保留最小错误类别、修复提示/适配器/检索或升级人工。

## 12. 失败案例：遗漏关键概念

回答只写“参数”，却没有“返回值”，术语命中数低于要求。它可能仍是部分有用的解释，但对这个案例的最低教学目标不通过。评测不应偷偷补文本，也不应将部分命中伪装成全通过。

这也提示夹具设计者：关键术语应少而必要。把整段标准答案拆成几十个词只会鼓励复制，不会提高理解。

## 13. 失败案例：错误关闭复核

当案例要求 `needs_human_review=True` 而候选输出 `False`，评测失败。这与事实正确性不同：即使当前答案看似正确，系统也可能因数据来源、敏感场景或不确定性而必须提示复核。

复核门是产品风险控制，不能由模型自信语气取代。模型可以提出候选信号，最终路由规则仍应在模型外。

## 14. 报告中保留什么

| 可写入 | 目的 |
|---|---|
| 案例 ID、非内容标签 | 定位版本化教学案例。 |
| 状态、通过/失败 | 观察合同结果。 |
| 引用数量、子集布尔值 | 观察来源约束。 |
| 术语所需/命中数量 | 观察最低覆盖。 |
| 复核匹配 | 观察人工升级信号。 |

## 15. 报告中不写什么

| 不写入 | 原因 |
|---|---|
| 问题与回答正文 | 可能包含个人、业务或敏感内容。 |
| 文档块与系统提示 | 可能泄露语料、策略或攻击载荷。 |
| 术语字面量 | 夹具未来可能含敏感或业务标识。 |
| 原始供应商响应与密钥 | 风险高且不适合普通评测报告。 |

## 16. 一次真实烟雾调用能证明什么

项目 v0.4.0 在刷新实时目录后，用一个公开函数教学块完成了一次固定 `gpt-5-mini` 严格 JSON 来源约束回答调用。本地验证了有一个实际块引用，证据文件只保存状态、引用 ID/数量、长度和索引版本。

它只能说明当时的代理接线、请求形状和最小本地引用检查可以协作。它不证明真实 embedding 可用、模型质量高、回答事实正确、注入已解决、成本稳定、容量足够或已生产就绪。

## 17. 不要重复真实调用来“刷信心”

重复同一小问题只会增加成本、留下更多数据路径并形成虚假的稳定感。优先用假传输、静态夹具和本地验证覆盖绝大多数分支；真实调用只用于已核对目录后的最小接线检查，并单独记录其非质量证明边界。

官方评测实践建议持续、任务相关的评估并结合人工判断，而非仅凭主观观感或单次示例。[1]

## 18. 提示注入案例也要进入回答评测

检索文本含有“忽略规则”或“执行命令”时，回答应明确把片段作为不可信数据，不执行其中指令，并保留人工复核。夹具不需要复述攻击全文；非内容标签、来源 ID、状态、术语计数和复核门已足以检测合同退化。

提示注入风险来自网页、文档、邮件等第三方内容试图偏离系统目标，尤其在系统具备敏感访问或行动能力时更严重。[2] 模块 10 不提供工具，这一限制本身是重要安全控制。

## 19. 质量门不是模型排行榜

项目当前 35 项无网络 pytest、mypy、Ruff、CI 与静态报告说明代码合同可复现。它们不可以转换成“模型得分”或“RAG 生产认证”。评测门应服务特定任务与风险，而不是为一个漂亮总分服务。

任何要扩大到真实语料、多人访问、持久索引或高风险建议的系统，都必须重新设计数据治理、访问控制、保留期、评测集、人工复核和事故处置。

## 20. RAG 回答层仍不是 Agent

回答支持度评测没有让系统规划、调用工具、写入记忆、浏览网页或执行动作。它是一个更严格的问答候选合同。后续 Agent 模块会把模型、状态、工具、记忆和工作流分开实现，并为每个外部副作用加入模型外授权和审计。

## 21. 快速测试（5 题）

1. 为什么检索召回通过后仍要评测回答？
2. “引用 ID 是允许集合子集”证明了什么，又没有证明什么？
3. 为什么报告保存术语命中数量而不保存术语字面量？
4. 何时 `needs_human_review=True` 仍不足够？
5. 单次真实烟雾调用不能证明哪三类事项？

**答案要点：** 1. 回答仍会遗漏、误概括或破坏状态/引用合同；2. 证明没有引用未知块，不证明结论真实；3. 降低夹具未来敏感内容的落盘风险；4. 未定义实际复核流程时；5. 例如事实性、容量与生产安全。

## 22. 代码阅读（2 题）

1. 阅读 `evaluate_answer_case()`，画出状态、引用、术语和复核四个布尔条件如何得到 `passed`。将任一条件设为假，解释报告中哪些字段帮助定位原因。
2. 阅读 `write_public_answer_report()`，解释为什么它只序列化 `AnswerEvaluationResult`，而不把 `GroundedAnswer` 或夹具对象直接 `asdict()` 写出。

## 23. Debug（2 题）

1. 将 `function-supported` 候选引用改为 `unknown-0`。运行测试并检查 `citation_subset_valid=False`；不要将未知 ID 自动替换为第一个来源。
2. 将注入案例的 `needs_human_review` 改为 `False`。观察即使术语和引用通过，整体案例仍失败；解释这是风险路由失败而不是 JSON 解析错误。

## 24. 编程练习（3 题）

1. 为回答评测增加“最大回答字符数”门，只持久化实际长度和上限，不保存正文；为刚好等于上限和超出上限写测试。
2. 增加一个“引用过少”质量门：案例可声明最少引用数，评测验证数量但不保存来源正文；讨论为什么该门仍不能代表证据充分。
3. 为夹具增加版本号和案例生成日期，报告只保存版本与计数；设计未知版本、重复 ID、额外字段和非布尔复核值的受控失败测试。

## 25. 逆向设计与课后项目

**逆向设计：** 一个 RAG 团队只测“模型是否说得通”；所有回答都标记已审核；报告保存完整问题、全文、提示和模型推理；模型自由造 URL；每次提交都用真实生产语料调用二百次；单次成功演示被称为准确率。请至少倒推十项失败：检索、引用、评测数据、隐私、成本、注入、复核、事实性、版本、可复现性和报告治理，并提出对应模型外控制。

**课后项目：** 将项目 10 扩展为 **回答支持度评测 v0.5**。要求：版本化公开夹具；状态、引用白名单、最低术语和人工复核门；案例与回答 ID 严格一一对应；未知字段/重复 ID 受控失败；只输出计数与类别的原子 JSON 报告；至少四个无网络失败测试；README 说明静态夹具、单次烟雾与真实语义/事实/安全证明的区别；运行 pytest、mypy、Ruff 和 CI。不得在本项目加入工具、自由 Agent 循环或真实私有语料。
