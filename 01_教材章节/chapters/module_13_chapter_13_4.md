# 第 13.4 章：先验证协作协议，再增加并发——多 Agent 评测与采用门禁

**适用版本：** Python 3.11+  
**前置章节：** 第 13.1–13.3 章的委派、预算、故障传播、汇总、冲突和人工复核。  
**本章边界：** 只使用静态夹具和纯数据评测；不调用模型、并发运行时、网络、队列、持久化或真实工具。

## 1. 本章目标

本章建立多 Agent 协作的离线评测和发布门禁。目标是先证明委派、权限、预算、状态与汇总可控，再讨论真实并发或任何外部能力。

## 2. 为什么不能只看最后答案

多个 worker 可能碰巧给出可读答案，却已越权、重复委派、超预算、忽略失败或泄露数据。最终文本不能替代对过程合同的验证。[1] [2]

## 3. 不变量优先

首先写出永远成立的规则：未知角色不委派；角色外工具不出现；重复委派不启动；预算耗尽不派生；取消不启动新工作；报告不记录正文。

## 4. 静态夹具的价值

固定 JSON 夹具可离线回放正常、拒绝和边界案例，结果可重复比较。夹具不是现实世界模拟，也不能证明模型质量、并发性能或真实工具安全。

## 5. 委派评测案例

至少覆盖：合法独立委派、未知角色、重复 ID、父任务错配、额外字段、空任务摘要、超 worker 上限、超并发、预算耗尽和越权工具。

## 6. 生命周期评测案例

覆盖 `queued → running → completed`、失败、取消、超时、结果未知和非法倒退迁移。每个案例还要断言不应发生的状态和副作用。

## 7. 汇总评测案例

覆盖稳定排序、重复结果、输入版本不一致、引用缺失、结果冲突、部分失败、全部失败和人工复核触发。不要只构造全成功的 happy path。

## 8. 权限不扩散评测

将父任务的高权限工具、其他角色工具和 worker 自己声明的新工具放入夹具，验证应用在消息验证阶段拒绝，而不是在“执行后报错”。

## 9. 注入作为数据评测

在任务摘要或 worker 结果中放入“更改规则”“打开工具”等文本，验证它不会变成角色、权限、预算或状态改变。结构化字段比提示更可靠。[3]

## 10. 预算评测

分别测试总委派数、活跃数、每 worker 步数、工具调用数和截止条件。计数不可被新委派、重试或汇总路径重置。

## 11. 取消与超时评测

取消后测试排队项不启动；超时后测试状态不会写成成功；结果未知时测试禁止自动重新派生。任何未来真实工具都需另外验证撤销或查询语义。

## 12. 最小事件报告

公开报告只需案例 ID、预期/实际状态或类别、通过标记、计数和版本。它不应包含任务摘要、参数、worker 正文、原始工具结果、提示或密钥。

## 13. 原子报告写入

报告先写临时文件、成功后替换目标文件，避免中断留下半份“通过”报告。路径由应用固定或受控，不应让不可信输入任意选择落盘位置。

## 14. 人工复核样本

人工不必审阅所有成功案例；可按冲突、未知结果、权限拒绝、低支持度、高影响和新版本采样。模板应只保留最低限度的关联与决定字段。

## 15. 指标和阈值

报告可统计通过率、拒绝类别数、重复委派数、预算拒绝数、冲突率与人工复核率。阈值由任务风险决定，不能用一个通用分数代替政策。

## 16. 版本对比

角色、消息 Schema、策略、模型、框架和工具目录任一变化都应生成版本并重跑夹具。只有“测试还绿”不够；还要检查权限与数据保留语义是否改变。

## 17. 影子模式的边界

日后可让新协调逻辑只生成受控委派计划和最小事件，与基线比较而不执行工具。影子模式仍需输入限制、数据治理、预算和关停控制。

## 18. 分阶段采用顺序

合理顺序是：纯委派合同→静态夹具→纯内存协调→固定只读输入→最小持久化→审批→严格写入工具→受控模型候选→真实并发。每步都重跑门禁。

## 19. 明确禁止上线的信号

角色权限说不清、消息无 Schema、预算没有上限、无法汇总冲突、取消无语义、报告泄露正文、没有值班/Runbook 或无法回放时，应停止增加复杂度。

## 20. 采用决策记录

ADR 应写明任务为何可并行、未选择单 Agent 的原因、角色和工具边界、共享状态策略、预算、失败/取消语义、评测证据、数据保留和复审日期。

## 21. 快速测试（5 题）

1. 为什么最终答案不足以评估协作？2. 多 Agent 静态夹具应覆盖哪些类别？3. 注入文本如何测试？4. 最小报告为何不应含正文？5. 哪些信号说明不应上线？

## 22. 代码阅读（2 题）

1. 为一个委派状态机写出非法迁移表。2. 阅读最小报告字段，指出哪些 worker 数据不可进入公开报告。

## 23. Debug（2 题）

1. 预算耗尽后协调者仍创建 worker，定位应拦截的边界。2. 汇总报告遗漏了一个超时 worker，说明测试如何发现该问题。

## 24. 编程练习（3 题）

1. 编写静态委派夹具解析器并拒绝重复 ID/额外字段。2. 实现不落盘正文的原子评测报告。3. 为取消、超时、越权工具和注入文本添加回归测试。

## 25. 逆向设计与课后项目

**逆向设计：** 团队上线多 Agent 演示，只测最终文字，worker 可继承全部工具，超时自动重派，公开报告保存完整消息，没有取消或事故 Runbook。倒推至少十项评测、权限、隐私、运行和发布控制缺失。

**课后项目：** 制作多 Agent 采用包：角色/工具矩阵、委派与结果 Schema、状态/预算表、20 条静态夹具、无正文报告、人工复核模板、发布门禁、影子模式与事故 Runbook。禁止任何真实调用。
