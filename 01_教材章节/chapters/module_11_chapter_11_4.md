# 第 11.4 章：能重放才可改进——受限 Agent 的评测、事件与人工复核

**适用版本：** Python 3.11+  
**项目连接：** `projects/11-bounded-agent-core/`（v0.1.0）  
**前置章节：** 第 11.1–11.3 章的有限状态、授权候选、审批、预算与静态夹具。

## 1. 本章目标

本章将“运行过一次”改造成“可以重复检查”。你将区分事件、日志、夹具、指标、报告和人工复核，并明确它们都不构成自动授权。

## 2. 为什么 Agent 更需要评测

Agent 的错误常发生在多步骤交界处：动作是否允许、何时停止、是否等待审批、工具是否被调用。只测最终文本会漏掉过程合同。[1]

## 3. 静态夹具的用途

项目的 JSON 夹具是一组公开、版本化输入。回放时使用固定假工具和固定动作序列，因此失败可以定位到应用逻辑，而非网络或模型波动。

## 4. 夹具不是生产流量

教学夹具不能代表真实用户、攻击者、行业任务或长尾失败。它是回归信号，应持续补充，但不能包装成真实安全或质量证明。

## 5. 案例 ID 是连接键

稳定 `case_id` 让夹具、结果、报告和人工复核关联。重复 ID 必须拒绝，否则两个不同案例会污染同一条证据。

## 6. 字段闭集为何重要

评测案例只允许约定字段。额外字段往往意味着版本漂移、误拼写，或试图把未评审能力带入回放。严格解析让失败及早出现。

## 7. 事件是最小过程事实

`AgentEvent` 记录任务 ID、步骤数、状态、动作和结果类别。它描述“发生了哪类受控转换”，而不是复制目标、参数或工具返回。

## 8. 日志不是用户报告

日志帮助维护者调试，应走标准错误且最小化；用户报告应走标准输出或受控文件。两者都不得记录密钥、提示、正文或完整供应商响应。

## 9. 为什么报告不含正文

评测报告用于趋势与门禁，只需案例 ID、期望状态、实际状态和通过标记。原始目标、注入文本、参数和工具结果会扩大数据保留与泄露面。

## 10. 原子替换的作用

先写临时文件、再替换目标，避免半截 JSON 被后续读取。原子替换保护文件完整性，不保证目录权限、跨机器一致性或业务成功。

## 11. 报告路径也要受控

CLI 固定报告名称，而不接受任意输出路径。这样可避免把“评测”悄悄变成任意文件写入能力；生产系统仍需更完整的存储权限设计。

## 12. 通过率的正确解释

`passed_count / case_count` 只表示当前夹具的合同通过比例。它不是模型准确率、用户满意度、事实正确率、攻击抵抗力或生产 SLA。

## 13. 失败比平均数更有用

分别观察预算耗尽、审批拒绝、非法动作、参数拒绝和状态矛盾。一个漂亮的平均数可能掩盖高风险路径全部失败。

## 14. 人工复核的输入

复核者应看到经批准的最小上下文、案例版本、预期/实际类别、复现命令与决定记录。不要默认把敏感原文推给每一位复核者。

## 15. 人工复核不能无限扩大权限

复核可以决定案例标注或上线门槛，却不能临时允许 shell、网络、支付或账户操作。权限变更需要独立威胁建模、审查与测试。

## 16. 提示注入案例如何评测

把“忽略规则”等文本放进夹具参数，验证它只作为数据经过纯工具路径，不能新增动作、批准审批或改写预算。提示词不是权限边界。[2]

## 17. 负向案例不可缺少

成功案例确认正常路径；重复 ID、额外字段、未知动作、空动作序列和冲突 CLI 参数确认默认拒绝。安全测试必须包含预期失败。

## 18. 可观察性不等于监控平台

本项目的最小事件适合教学和单元测试。生产可观察性可能需要 trace、指标、告警、访问控制、保留期限和事件关联，但先确保不泄露正文。[3]

## 19. 版本化与可比较性

改变案例字段、动作枚举、预算或停止原因时，应更新版本、测试和报告解释。否则两个“通过率”可能测量了完全不同的合同。

## 20. 发布门禁的顺序

先运行单元测试、类型检查、静态检查和静态夹具；再决定是否允许有限人工试用。没有完成可重放的离线门禁，不应直接把 Agent 接到现实副作用。

## 21. 快速测试（5 题）

1. 静态夹具解决什么问题？2. 为什么案例 ID 不能重复？3. 报告为何不含工具结果正文？4. 原子替换不保证什么？5. 通过率为什么不是安全证明？

## 22. 代码阅读（2 题）

1. 阅读 `write_public_evaluation_report()`，标出持久化的字段和故意未持久化的数据。2. 阅读 `run_static_cases()`，解释重复 ID 与额外字段在哪一层拒绝。

## 23. Debug（2 题）

1. 向夹具加入未允许字段，观察稳定错误。2. 在 `--run-static-evaluation` 与 `--write-static-report` 同时出现时，确认 CLI 拒绝冲突模式。

## 24. 编程练习（3 题）

1. 增加报告模式版本字段，保持正文最小化。2. 添加状态—事件一致性检查并写负向测试。3. 设计人工复核 CSV 的字段闭集，禁止目标和工具结果正文。

## 25. 逆向设计与课后项目

**逆向设计：** 一个团队只保存最终回答、允许任意 JSON 字段、案例 ID 可重复、评测可写任意路径、通过率自动打开工具权限。倒推至少八项测试、隐私、权限和发布控制缺失。

**课后项目：** 为纯工具 Agent 实现三类静态案例、严格夹具解析、最小事件、原子无正文报告、固定 CLI 报告模式、人工复核模板和 pytest/mypy/Ruff 门禁。禁止模型、网络和真实副作用。
