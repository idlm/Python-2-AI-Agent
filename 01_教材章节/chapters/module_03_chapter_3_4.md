# 第 3.4 章：日志、调试与异常处理——让自动化在失败时可诊断

## 1. 本章目标
使用日志记录关键事件，区分调试信息与用户提示，并为可预期失败设计异常边界。

## 2. 为什么学习
自动化失败不可避免；没有证据，就无法安全恢复或改进。

## 3. Agent 中的作用
Agent 轨迹、工具错误、重试和状态恢复都依赖可关联的日志与异常策略。

## 4. 前置知识
完成第 0.3 章与模块 3 前三章。

## 5. 概念解释
日志记录运行事实；调试定位错误原因；异常处理决定预期失败如何传递、转换或恢复。

## 6. 生活化比喻
日志像飞行记录器，异常处理像应急流程；两者都不能在事故后临时编写。

## 7. 原理分析
捕获过宽异常会掩盖缺陷；应在知道如何处理的位置捕获特定异常，记录上下文后决定重试、跳过或停止。

## 8. 最小示例
```python
import logging
logging.basicConfig(level=logging.INFO)
try:
    text = open("missing.txt", encoding="utf-8").read()
except FileNotFoundError:
    logging.warning("输入文件不存在")
```

## 9. 逐行解释
配置日志级别；尝试读取；仅捕获缺失文件；记录可读警告而不伪造成功。

## 10. 常见错误
不要使用空 `except`；不要把密钥写入日志；不要把 `print` 当唯一生产诊断工具。

## 11. Traceback 分析
未处理异常保留 Traceback；处理后仍应记录文件、操作和错误类型，以便复现。

## 12. 错误案例
归档失败后捕获所有异常并继续，最终报告“全部成功”，但部分文件未移动。

## 13. 改进方案
为每项操作记录成功、跳过和失败；汇总结果；对可恢复错误给出重试或回滚策略。

## 14. 工程实践
使用模块级 logger、统一格式、关联 ID 与结构化字段；测试正常和失败分支。

## 15. 性能优化
避免高频循环中无意义日志；对大量事件使用恰当级别和批量汇总。

## 16. 安全问题
日志脱敏；异常消息面向用户时隐藏内部路径、密钥和堆栈，详细信息写入受控日志。

## 17. 小项目
为自动归档 Dry Run 记录每个候选文件、决策和最终汇总，不执行移动。

## 18. 单元测试
模拟文件不存在，断言返回安全结果、产生警告且不报告成功。

## 19. 自测题
1. 日志与 print 区别？ 2. 为什么捕获具体异常？ 3. 何时重试？ 4. 如何脱敏？ 5. 为什么失败不能伪造成功？

## 20. 代码阅读题
