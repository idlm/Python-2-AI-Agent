# ADR-001：模型输出不是权限来源

**状态：** 已采纳  
**日期：** 2026-08-26  
**关联章节：** 9.1–9.3、10.3–10.4、11.1–11.4、12.3、13.1、14.3、15.4

## 背景

LLM 可以生成自然语言、JSON 或工具调用候选，但输出可能不符合 Schema、权限、预算、来源、事实或当前状态。提示词和框架节点都无法替代应用层访问控制。

## 决定

全书统一采用以下边界：模型/规划器**只提出候选**；应用代码在任何执行前验证固定 Schema、字段闭集、状态、动作/工具允许列表、参数、预算、身份、审批、幂等/重放语义和结果类别。高风险或真实副作用不由模型文本、系统提示、框架配置或评测通过自动授权。

## 后果

这一决定增加了数据模型、测试、评测夹具和状态机的实现成本，但带来可审计的失败边界和可复现的离线验证。课程中的项目 9–15 因此默认使用静态夹具、纯数据合同或纯工具替身；它们不直接等同于生产 Agent。

## 已拒绝替代方案

| 替代方案 | 拒绝原因 |
|---|---|
| 只依赖系统提示约束模型 | 提示不是权限边界，不可信输入仍可能影响模型行为。 |
| 只依赖供应商 strict JSON 输出 | 结构合规不验证领域、权限、预算、来源或结果语义。 |
| 让框架节点自动执行模型建议 | 框架编排不等于应用级能力授权。 |
| 以人工 UI 点击替代应用验证 | 人工确认不能补偿未知参数、过期状态或越权工具。 |

## 验证证据

模块 9 的严格 JSON 本地重复验证、模块 10 的来源白名单、模块 11 的固定动作/预算/审批、模块 12 的执行前再验证、模块 13 的权限不扩散，以及模块 14–15 的发布和运行准备门禁均覆盖此决定。
