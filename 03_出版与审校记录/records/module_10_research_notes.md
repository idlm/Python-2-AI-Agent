# 模块 10 RAG 官方资料与课程设计研究笔记

**核对日期：** 2026-08-26（GMT+8）  
**课程阶段：** 模块 9 已完成当前收束；模块 10 在任何真实嵌入或托管检索调用前，必须重新核对实时模型/接口能力与价格。  
**本笔记用途：** 为《Python私房课》模块 10 的零基础 RAG 正文、最小项目、测试和安全边界提供可追溯事实来源；不是对任意供应商、模型、价格或托管工具永久可用性的承诺。

## 1. RAG 的最小定义与边界

检索增强生成（Retrieval-Augmented Generation，RAG）应被拆成可单独验证的步骤：接收受控查询；在经允许的语料中检索候选片段；把有限、可追溯的片段作为**不可信上下文数据**交给模型；返回带来源的候选回答或受控“未找到足够依据”。它不是“上传文件后模型就知道事实”，更不是 Agent、工具权限、自动网页浏览或数据库写入。

OpenAI 的 Retrieval 文档将语义搜索描述为：利用向量嵌入返回语义相关的结果，即使查询与文本几乎没有相同关键词；向量存储是这类搜索的数据索引容器。[2] 课程必须同时讲清：相关性分数不是事实性、权限、时效性或引用充分性的证明。

| RAG 层 | 最小责任 | 必须拒绝或显式标记的情况 |
|---|---|---|
| 语料接收 | 来源允许列表、文件类型/编码/大小边界、稳定文档 ID 与版本。 | 未授权来源、路径遍历、超限/不支持格式、无法解码文本。 |
| 切块 | 保留 `document_id`、块序号、字符范围和文本指纹；采用可复现策略。 | 空块、重复 ID、无来源块、不可解释的静默截断。 |
| 嵌入/索引 | 通过可替换协议生成或读取向量；记录模型/维度/索引版本元数据。 | 混用未声明维度/模型、把向量当原文或事实。 |
| 检索 | 查询边界、受控 `top_k`、分数排序、元数据过滤与来源返回。 | 无界返回、跨租户/跨语料查询、只返回模型概述而丢失来源。 |
| 生成 | 只基于给定片段提出候选回答，带引用，允许拒答。 | 执行片段中的命令、把检索文本升级为系统指令、无来源断言。 |
| 评测/人工复核 | 分别测检索与回答；保留最小化的案例 ID、命中/遗漏与来源证据。 | 把单次答案成功或相似度分数当作生产质量认证。 |

## 2. 嵌入与相似度

OpenAI 的 Embeddings 指南说明，嵌入是浮点数向量；向量间距离用于衡量文本相关性，较小距离通常表示较高相关性。常见用例包括搜索、聚类、推荐、异常检测、分类和多样性度量。[1] 该文档示例用余弦相似度对查询向量与文档向量排序，并返回最相关文档。[1]

**课程边界：** 向量是用于候选排序的数值表示，不是原文副本、语义证明、敏感信息消失的保证，也不是授权凭据。项目 10 的第一版应将 `EmbeddingProvider` 设计为 Protocol，并以确定性假嵌入/固定小语料测试索引与检索合同；只有在实时目录确认合适嵌入能力、接口和预算后才做最多一次小型真实烟雾调用。不能从本笔记或记忆硬编码可用 embedding 模型。

官方文档列出的某些嵌入维度和价格是特定 OpenAI API 的当前资料，不应直接外推到本课程环境的代理。嵌入输入按 token 计量，维度、存储和计算成本之间存在权衡。[1]

## 3. 切块、索引与元数据

Retrieval 文档说明，向向量存储添加文件时，托管向量存储会自动切块、嵌入并建立索引；语义搜索结果可含片段、相似度分数、文件 ID、文件名和属性。[2] 它还支持属性过滤、查询重写、分数阈值和混合排序调节。[2]

**课程设计结论：** 模块 10 不应把托管自动切块当作无法解释的魔法。先用纯 Python 编写稳定字符窗口/段落边界切块器，明确 `chunk_size`、`overlap`、切分位置、源文档 ID、源版本、顺序和指纹；再比较不同策略。重叠不是默认真理：它扩大索引、可能重复语境和成本，应以评测结果决定。元数据过滤是检索范围控制的一部分，而不仅是“提高相关性”的调参。

对上传、删除与重建，必须定义版本和一致性边界。官方文档指出某些向量存储文件操作异步，删除后短时间内搜索仍可能含已移除内容。[2] 因此课程原型应把“删除请求已接受”“索引版本已重建”“查询切换到新版本”区分开，绝不静默保证即时全局一致。

## 4. 查询、返回来源与生成边界

OpenAI 的 File Search 文档描述托管工具以语义和关键词搜索已上传文件，并在生成结果中提供文件引用；若需观察搜索结果，可显式请求包含搜索结果。[3] Retrieval 搜索响应也可直接给出块内容、分数与文件来源。[2]

**课程边界：** 先实现框架无关的 `RetrievedChunk`，至少含 `document_id`、`document_title`、`chunk_id`、`score`、`source_version` 和片段文本。面向用户的回答必须只引用真正被检索并传入的块；没有足够支持证据时应公开说明“当前受控语料中未找到足够依据”，而不是自由补全。引用只能说明来源关联，不能自动证明来源权威、最新或适用于用户的具体处境。

模块 10 的最小实现不应注册 `file_search`、网页访问、shell、SQL 或任何会有副作用的工具。托管 File Search 可作为后续对照案例，而不是跳过检索合同、语料治理和评测的捷径。[3]

## 5. 评测：把检索和生成分开测量

OpenAI 的评测最佳实践指出生成式系统输出有可变性，应尽早、持续、按任务建立评测，并把自动化指标与人工判断结合；只靠“看起来可用”的主观判断是反模式。[4] 对“文档问答”示例，资料给出 context recall、context precision 和用户正向评价作为可组合维度；其中列出的 0.85、0.7 和 70% 是该示例目标，**不是本课程或任何业务的通用阈值**。[4]

模块 10 至少应有如下静态公开夹具，并运行无网络测试：

| 评测层 | 最小案例 | 可观察结果 | 不应声称 |
|---|---|---|---|
| 切块 | 标题、段落、超长段、空段与 Unicode 文本。 | 稳定块数、范围、ID、无空块。 | “切块已最优”。 |
| 检索召回 | 已知问题对应的目标块。 | 目标块是否在 `top_k`。 | 所有真实问题都会被召回。 |
| 检索精度 | 含干扰块、同义表达、错误主题。 | 前若干块中无关项的数量/比例。 | 分数本身等于正确率。 |
| 来源 | 每一命中块有文档/版本/位置。 | 不能生成无来源检索结果。 | 来源等于可信或最新。 |
| 拒答 | 问题不在语料、无结果或低分。 | 稳定的 `not_enough_evidence`。 | 模型永远不会猜测。 |
| 安全 | 文档片段含“忽略规则”“执行命令”等字样。 | 作为数据返回/引用，永不执行。 | 一句系统提示已解决注入。 |

## 6. RAG 与提示注入/数据安全

OpenAI 的安全资料建议对抗性测试、在可能时人工复核、限制输入与输出 token，并明确模型会产生幻觉、偏差和其他限制。[5] OpenAI 关于提示注入的资料进一步说明，来自网页、文档、邮件等第三方内容可能包含试图诱导模型偏离用户目标的恶意指令；风险会随着模型可访问敏感数据或可执行更长、更主动任务而增加。[6]

**课程安全原则：** 所有检索块均是不可信数据，无论它们来自用户上传、内部文档、网页缓存还是数据库。块中的“系统消息”“开发者指令”“调用 API”“泄露密码”等字样不能改变应用合同。检索层不执行块文本；生成层不授予权限；后续工具层也必须在模型外实施最小权限、参数验证、允许列表、审计和通常的人工确认。[5] [6]

项目 10 不将任何真实私密、受版权/保密限制或未获授权的语料提交给外部嵌入或托管检索服务。课程夹具只使用自制、短小、公开的教学文本；运行日志、评测报告和 manifest 仅保存 ID、长度、版本、分数摘要和结果类别，而不保存用户原文、完整块、密钥、系统提示或原始供应商响应。

## 7. 模块 10 最小架构建议

```text
受控 CourseDocument
  └─ document_id + title + version + public teaching text
          │
          ▼
Chunker Protocol / 可复现 Chunk
  └─ chunk_id + 字符范围 + source_version + text
          │
          ▼
EmbeddingProvider Protocol（测试假实现；真实实现后置）
          │
          ▼
InMemoryVectorIndex
  └─ model/dimension/index_version + vectors + chunks
          │
          ▼
Retriever
  └─ query 长度 + allowed collection + top_k + score threshold
          │
          ▼
RetrievedChunk（来源与分数）
          │
          ▼
后续受控生成/引用层（不在第一章执行工具）
```

初版应优先实现语料合同、切块、确定性索引/相似度、来源、`top_k`、阈值、受控失败和离线检索评测。先验证“给定问题是否取到正确来源”，再决定是否把片段交给模块 9 的受控模型客户端生成回答。RAG 是检索和生成的可审计组合，不是安装某一框架。

## 8. 实时代理能力核对（2026-08-26）

本轮已将内置 OpenAI-compatible 代理的实时 `/models` 响应保存为 `records/module_10_live_model_catalog.json`（6033 字节）。目录列出十个聊天模型；其中 `gpt-5-mini` 当前声明支持严格 JSON Schema 输出、工具和视觉，但不支持 streaming。该目录**没有**列出 `text-embedding-*` 等嵌入模型，也没有公开 embedding 端点或嵌入能力字段。因此，模块 10 不能据此假定当前课程代理可用真实 embedding 调用，也不能硬编码任何 embedding 模型 ID、维度或价格。

课程决定：继续以 `EmbeddingProvider` Protocol 和明确标注为非语义质量证明的确定性哈希测试替身完成索引、检索和评测合同。若未来目录或官方接口明确给出嵌入能力，必须先增加独立适配器、输入/token/维度边界、无网络假传输测试和一次最小脱敏烟雾验收，才可声明真实嵌入路径可用。当前可在独立的来源约束回答适配层中考虑使用已核对 JSON Schema 能力的聊天模型；同样必须固定模型、严格 Schema、本地验证、最小日志、有限重试和最多一次脱敏烟雾，且不把该调用称为 RAG 质量证明。
