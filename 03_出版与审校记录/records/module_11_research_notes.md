# 模块 11 研究笔记：无框架 Agent 的状态、工具与受控循环

**核对日期：** 2026-08-26（GMT+8）  
**用途：** 为《Python私房课》模块 11 的零基础正文、项目、测试和安全边界提供可追溯资料；不是任何框架、模型、价格或自动执行能力的永久承诺。

## 1. Agent 不是框架名称

Agent 应作为一个可检查的运行系统理解：它在多步任务中保存足够状态，基于模型候选选择下一步，调用受控工具，从环境结果获得反馈，并在完成、失败、预算耗尽或人工审批处停止。OpenAI 的 Agents SDK 指南把应用描述为能够规划、调用工具、协作并保持多步工作状态的系统；同一指南明确区分由应用自己管理循环的 API 工作流和由 SDK 运行循环的 Agent 运行。[1]

Anthropic 将 **workflow** 区分为由预先定义代码路径编排的 LLM/工具系统，将 **agent** 区分为模型动态决定过程和工具使用的系统。[3] 课程结论是：先用 Python 状态机、固定工具和显式循环实现最小 Agent，再比较任何框架；框架不能替代状态、授权、失败处理、评测或审计设计。

| 层 | 最小责任 | 禁止假设 |
|---|---|---|
| 任务状态 | 保存允许目标、当前阶段、步数、结果摘要和停止原因。 | 状态等于记忆、状态自动持久或跨重启可靠。 |
| 规划候选 | 提出固定下一步类别。 | 模型文本自动获得执行权。 |
| 工具合同 | 固定名称、参数 Schema、允许列表、资源预算和公开结果。 | 任意 Python callable、shell、SQL、URL 或用户文本可直接执行。 |
| 调度循环 | 执行一次、验证结果、更新状态、检查停止条件。 | 无限循环、静默重试或不受限自治。 |
| 审批/审计 | 对有副作用或敏感访问前暂停并给人可审查摘要。 | 复核布尔值等于已批准或已执行。 |

## 2. 先选 workflow，再选 Agent

Anthropic 的工程指南建议从最简单方案开始，仅在复杂性有可测量价值时增加 Agentic 系统；工作流适合定义明确、需要可预测性的任务，Agent 更适合无法预知步骤数量且需要模型驱动决策的开放问题。[3] 因此模块 11 的项目先实现：固定步骤上限、固定工具允许列表、有限状态、测试替身规划器和离线夹具。只有在固定 workflow 无法表达合理分支时，才让受审查的规划器从小枚举中选择下一步。

> 课程规则：**模型决定候选，应用决定是否能执行。**

## 3. 工具和权限必须在模型外

OpenAI 的安全指南说明提示注入可来自不可信文本或数据，可能诱导模型改变行为、泄露私人数据或调用下游工具；风险随任意文本影响工具调用而增加。[2] 该指南建议将不可信输入置于用户消息等低权限数据通道，节点间使用结构化输出限制自由文本流，并为工具操作保留审批。[2]

模块 11 因此不从模型输出导入 callable，不开放 shell、文件写入、网络、数据库、MCP、支付或账户动作。首个工具只允许纯函数、公开课程数据、严格参数和无副作用返回。后续新增任何副作用工具都必须拥有独立参数 Schema、允许列表、最小权限、超时、幂等/重复语义、审计、测试和通常的人工确认。

## 4. 状态、停止条件与人工介入

Agent 循环至少有：允许任务类型、最大步骤数、最大工具调用数、每步时间预算、失败类别、完成条件和 `waiting_for_approval` 状态。Anthropic 指出 Agent 通过环境工具结果获得 ground truth，并可在检查点或阻塞时暂停请求人工反馈；最大迭代等停止条件有助于保持控制。[3]

对于本书的最小原型，`waiting_for_approval` 仅生成一个不可伪造的待审批操作摘要；它不执行，也不把模型产生的“approved”文字当批准。批准必须由应用调用明确方法，以预期任务 ID、操作 ID 和批准人受控标识完成，并在审计中记录最小元数据。

## 5. 可观察性与评测

OpenAI 指南建议使用 traces 先调试，再进入评测循环，并把追踪覆盖模型调用、工具、Agent、guardrail 和 handoff 等运行事件。[1] 模块 11 不绑定追踪供应商，而是先定义最小 JSONL/内存事件：任务 ID、步骤编号、状态转换、固定动作类型、工具名、结果类别、耗时/计数、停止原因；不保存用户正文、系统提示、秘密、原始模型文本或工具敏感返回。

评测应分层：状态转移合法性、工具参数拒绝、预算停止、审批暂停/恢复、提示注入文本不执行、失败可解释性和最终公开视图。OpenAI 安全资料建议使用 trace graders 与评测理解决策和工具调用中的错误，但也提醒组合技术只能降低、不能消除风险。[2]
