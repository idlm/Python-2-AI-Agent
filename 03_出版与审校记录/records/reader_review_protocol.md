# 读者审校协议：零基础可用性与工程可复现性

**目的：** 让后续人工试读者以一致方式审阅《Python私房课》的语言、练习、运行命令和失败边界。该协议不要求试读者使用真实模型、秘密、云、部署平台或生产数据。

## 1. 试读者范围

| 角色 | 建议范围 | 主要关注点 |
|---|---|---|
| 零基础读者 | 模块 0–2 | 首现术语是否解释、命令是否可复制、错误是否可理解。 |
| 有基础 Python 读者 | 模块 3–8 | 合同、文件/网络/服务边界、测试与项目迁移是否连贯。 |
| AI/Agent 开发读者 | 模块 9–15 | 模型外授权、来源、评测、框架、委派、运行准备边界是否清楚。 |
| 工程审校者 | 全书 | 项目路径、测试命令、引用、索引、ADR、Runbook 与状态记录一致性。 |

## 2. 单章试读任务

每位试读者对选定章节完成下表的最小任务，并记录耗时和阻塞点。

| 步骤 | 任务 | 通过标准 |
|---:|---|---|
| 1 | 用自己的话复述本章目标与非目标。 | 能说明“解决什么”和“明确不解决什么”。 |
| 2 | 运行一个正文代码示例或项目验证命令。 | 命令、工作目录、预期输出和失败边界可定位。 |
| 3 | 完成一个快测与一个代码阅读题。 | 能从正文找到推理依据，而不是猜 API。 |
| 4 | 完成一个 Debug 题。 | 能区分 Traceback、公开错误和应写入测试的失败。 |
| 5 | 审阅课后项目映射。 | 路径存在、命令可运行、扩展任务不扩大未授权能力。 |
| 6 | 检查外部资料与术语。 | 行内引用、References、索引与术语表能互相定位。 |

## 3. 问题分类

| 类别 | 定义 | 严重度 |
|---|---|---|
| 阻断 | 无法开始、命令失效、项目路径不存在、练习缺关键前置知识、错误地鼓励不安全操作。 | P0 |
| 误导 | 概念、错误边界、模型/工具权限、真实烟雾或替身性质表达错误。 | P0/P1 |
| 不清楚 | 有多种合理理解、术语未定义、步骤跳跃、输出/失败预期不明确。 | P1 |
| 可用性 | 命令过长、表格难读、代码行号缺失、练习题没有足够线索。 | P2 |
| 文案 | 语病、术语不一致、标点、链接文本或标题不统一。 | P2 |

## 4. 反馈模板

```text
章节：
试读者角色与 Python 版本：
任务编号：
工作目录与运行命令：
预期结果：
实际结果：
问题类别与严重度：
最小复现输入（不得包含秘密、用户正文、prompt、真实端点或原始响应）：
建议修改：
是否影响后续章节：
```

## 5. 不应收集的信息

反馈不得包含 API 密钥、账号、用户数据、生产配置、完整日志、完整 Traceback、提示词、供应商原始响应、真实文件正文、数据库导出或生产端点。需要诊断时，优先使用课程已有公开夹具、最小状态/错误类别和可复现命令。

## 6. 处理节奏

P0 问题在下一审校前阻断发布；P1 问题进入当前修订批次；P2 问题可聚合后处理。每次修订都应补充/更新对应测试、索引、ADR、Runbook 或出版门禁，并记录验证证据。
